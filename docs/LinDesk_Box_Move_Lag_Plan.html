LinDesk Box 移动卡顿与撕裂修复计划

状态：分析完成 · 待 antigravity 执行 涉及：LinBox / ListView / LinDesktop 不改代码 · 仅记录根因与修复方案

1. 问题现象

在不开启毛玻璃（m_glassEffect == false）的情况下，拖动收纳盒（Box）依然严重卡顿、掉帧，并出现大面积白底 / 黑底 / 断裂花屏的撕裂与残影。经验证，该问题与毛玻璃无关，根因是 LinBox 移动时强制同步重绘 + 跨图层半透明脏矩形未通知底层壁纸宿主共同导致。

一句话根因：每移动 1 像素执行同步阻塞 parent->repaint()（只重绘透明的中间层 ListView，不刷新底层壁纸 LinDesktop），旧区域残留直接暴露为撕裂；叠加每像素 raise() 改窗口 Z-Order，进一步放大闪烁。

2. 桌面分层架构（撕裂产生的基础）

LinDesktop（底层）—— 绘制桌面壁纸的宿主窗口
　· 主程序顶层窗口：main.cpp:130 栈对象 + show()
└── ListView（中间层）—— 透明背景 WA_TranslucentBackground，绘制桌面图标并作为 Box 容器
　· LinDesktop.cpp:139 listView = ListView::instance(this)（parent 即 LinDesktop）
　· ListView.cpp:319 setAttribute(Qt::WA_TranslucentBackground)
　　└── LinBox（上层）—— 半透明背景（如 70% 不透明度）的收纳盒
　· LinBox.cpp:3990 注释确认 parentWidget 为 ListView（透明）

关键事实：壁纸不在 ListView 上绘制，而是在更底层的 LinDesktop（及组件/动态壁纸画布）。因此调用 parent->repaint() 只强制重绘透明中间层，底层壁纸未收到任何重绘通知——Box 移开后，旧位置没有真正被壁纸刷新，直接把未合成的透明缓冲区暴露在屏幕上。

3. 根因分析（逐点代码证据）

3.1 【致命阻塞与撕裂源】每移动 1 像素强制执行同步 repaint

LinBox.cpp:1207-1215 moveEvent()：

void LinBox::moveEvent(QMoveEvent* event) { if (QWidget* parent = parentWidget()) { if (!event->oldPos().isNull() && event->oldPos() != event->pos()) { const QRect oldRect(event->oldPos(), size()); const QRect newRect(pos(), size()); const QRect dirty = oldRect.united(newRect).adjusted(-12, -12, 12, 12); parent->update(dirty); parent->repaint(dirty); // <-- 致命点：无论开不开毛玻璃，每移动 1 像素强行阻塞 repaint！ }

机制：鼠标只要稍微移动，moveEvent 就被连续触发；repaint() 是同步阻塞调用，会强行中断常规事件循环队列、立即执行 ListView::paintEvent（其中包含小组件画布合成与数百个图标的相交测试）。在 125Hz~1000Hz 鼠标滑动下，一秒钟内触发几十上百次父窗口全套重绘，主线程被直接拖死。

后果：拖动瞬间严重卡顿、光标跟随掉帧；update() 与 repaint() 并存时，后者会立即执行全部挂起更新，前者的异步合并机制被完全架空。

3.2 【撕裂与残影根因】父控件透明，壁纸在祖父窗口 LinDesktop 上

分层见第 2 节。当代码调用 parent->repaint(dirty) 时，它只强制重绘了中间层 ListView；而 ListView 是完全透明的（WA_TranslucentBackground），底下的壁纸根本没有收到重绘通知。结果：Box 移开后的旧区域（oldRect）没有被真正的壁纸刷新，直接把透明/未合成的中间缓冲区暴露在屏幕上，表现为白底、黑底、断裂花屏。

项目内已有正确先例：LinDesktop.cpp:498-502 clearSelectionOverlay() 清除框选残影时，正是采用"透明层 update + mapTo(this, …) 映射坐标 + LinDesktop update"的跨层刷新模式。本次修复可直接复用该模式（见第 4 节），无需发明新机制。

3.3 【无意义的系统级重排】每移动 1 像素执行一次 raise()

LinBox.cpp:1235（moveEvent 尾部，无条件执行）：

raise(); // 每移动 1 像素调用一次！ QWidget::moveEvent(event); if (!m_isCapturingBackground && m_glassEffect && event->oldPos() != pos()) { scheduleBlurRefresh(); }

机制：raise() 会调用 Windows 系统 API 改变窗口 Z-Order，迫使系统窗口管理器重新计算层叠与非客户区；在移动过程中每像素反复调用，引发剧烈的画面闪烁与抖动。

3.4 【定时器内再次暴力双重 repaint】移动停止 30ms 后又同步重绘两次

LinBox.cpp:1217-1231 m_moveRefreshTimer（30ms 单次）回调：

m_moveRefreshTimer = new QTimer(this); m_moveRefreshTimer->setSingleShot(true); m_moveRefreshTimer->setInterval(30); // 30ms 无移动后再刷 connect(m_moveRefreshTimer, &QTimer::timeout, this, [this]() { if (QWidget* p = parentWidget()) { const QRect d = geometry().adjusted(-16, -16, 16, 16); p->update(d); p->repaint(d); // 同步重绘，立即刷新合成缓冲 } update(); repaint(); // 自身也再同步重绘一次 });

后果：即使移动已停止，还会以 30ms 延迟额外执行两次强制同步重绘（父窗口 + 自身），进一步加剧掉帧与残影窗口期。

4. 修复方案（三条核心 + 复用既有跨层模式）

4.1 彻底移除所有强制同步 repaint()，改用异步合并 update()

  • 删除 moveEvent 中的 parent->repaint(dirty)（LinBox.cpp:1214），保留 parent->update(dirty)，由 Qt 的垂直同步机制自动以最高帧率合并渲染；
  • 删除 m_moveRefreshTimer 回调内的 p->repaint(d) 与 repaint()（:1225/:1228），仅保留 update() 异步刷新。
等价性说明：update() 与 repaint() 最终执行的是同一个 paintEvent；区别仅是"排入事件循环合并渲染"与"立即阻塞执行"。因此该改动不改变任何绘制内容与最终画面，仅消除主线程阻塞。

4.2 跨图层将脏矩形同步通知给真正的壁纸宿主 LinDesktop

Box 移动时，不仅通知 parent->update(dirty)，同时把脏矩形从 Box → ListView → LinDesktop 逐层映射坐标，并通知底层壁纸窗口刷新。直接复用 LinDesktop.cpp:498-502 的既有模式：

// LinBox::moveEvent 内（替换 1212-1214 的写法） const QRect dirty = oldRect.united(newRect).adjusted(-12, -12, 12, 12); if (QWidget* p = parentWidget()) { p->update(dirty); // 中间层：图标/画布 if (QWidget* host = p->parentWidget()) { // 壁纸宿主：LinDesktop（按实际层级向上定位） const QPoint topLeft = p->mapTo(host, dirty.topLeft()); host->update(QRect(topLeft, dirty.size())); } }

这样 Qt 在一次合成周期内由下至上先画壁纸、再画图标、最后画半透明 Box，彻底消除撕裂、破损和残影。

4.3 移除 moveEvent 中多余的 raise()

  • 删除 LinBox.cpp:1235 moveEvent 尾部的无条件 raise()；
  • Z-Order 提升只保留在鼠标按下进入移动的入口（现有按下/双击/进入交互处已有点，确认保留即可），移动过程中保持稳定层级。

5. 实现注意（anti 执行时逐条对照）

注意点说明
壁纸宿主定位不要硬编码 parentWidget()->parentWidget()：建议按类型向上查找（qobject_cast<LinDesktop*> 或沿 parentWidget() 链搜索），兼容未来层级变化（如组件画布层插入）；若宿主为组件 CanvasWidget，则通知该层而非仅 LinDesktop
动态壁纸 / 组件画布层当前壁纸可能由组件系统 CanvasWidget 合成（非 LinDesktop::paintEvent 直绘）。修复后需在真机验证：壁纸为静态图 / 动态视频 / 组件壁纸三种情况下，拖动 Box 均无残影；若 Canvas 层独立，应把脏矩形同步通知到该层
同源 repaint 点LinBox.cpp:1952-1954（交互结束后的毛玻璃刷新）也使用了 p->repaint(…) + repaint()：一次性低频调用，非卡顿主因，但建议顺带统一为 update()，保持"全文件无强制同步 repaint"
定时器去留m_moveRefreshTimer 若仅用于"移动停止后补刷"，在 4.1/4.2 落地后可整体删除（update 已覆盖）；若保留则回调内只保留 update()
resize 同理resizeEvent（LinBox.cpp:1242+）若存在同类同步重绘/raise 逻辑，一并按同一原则处理（本次分析以 moveEvent 为准，resize 需 anti 顺带排查）
毛玻璃开关兼容本修复不触碰 captureBackgroundPixmap / updateBlurCache 链路（那是上一份毛玻璃性能报告的范畴）；两者独立，修复后可叠加生效

6. 验收清单

  • 功能不变：Box 可正常创建、移动、调整大小、合并收纳；布局持久化（layout.json）不受影响；右键菜单、框内多选、图标归属全部照旧；
  • 性能：拖动 Box 全程无卡顿、光标平滑跟随（与毛玻璃开关无关）；
  • 画面：移动过程中及停止后均无白底/黑底/撕裂/残影；Box 半透明效果正确叠加在壁纸之上；
  • 层级：移动过程中 Box 不被其他 Box/图标遮挡（按下时置顶语义保留）；
  • 回归：静态壁纸 / 动态壁纸 / 组件壁纸三种壁纸模式下拖动均无残影；开启毛玻璃时拖动不卡顿（与上份报告修复叠加验证）。
