LinDesk 微软商店应用图标兼容方案

对象：UWP / MSIX（Microsoft Store）应用图标在桌面的显示 · 2026-10-14（含黑边/清晰度回归修复 T6-T9） · 执行人：anti

问题：微软商店（UWP/MSIX）应用没有传统 exe 图标，现有图标链路（SHGetFileInfo / SHGetImageList / QFileIconProvider）在 Win11 上对这类应用不可靠，会返回白色或通用图标。

方案：主路径换用 IShellItemImageFactory（Shell 原生解析，高清、不依赖文件路径）；失败时用 AUMID + AppxManifest 兜底读取应用 logo。

1. 现有链路与失效原因

当前图标获取集中在 ListItemData::initIcon()（src/models/data/ListItemData.h:283 起），按类型分路：

类型现有实现对 Store 应用的问题
SpecialFolder SHGetFileInfoW(PIDL) → SHGetImageList(SHIL_JUMBO) 取系统 ImageList 图标 依赖 Shell 图标缓存，Store 应用缓存缺失/损坏时返回白色占位（Win11 已知问题）
.appref-ms SHGetFileInfoW(SHGFI_ICON | SHGFI_LARGEICON) 同上，依赖缓存
普通文件 / .lnk QFileIconProvider（内部走 SHGetFileInfo）+ symLinkTarget() 解析目标 QFileIconProvider 只拿 16/32 小图标；symLinkTarget() 对 UWP 快捷方式返回 AUMID（非文件路径），拿不到真实图标

根因：微软商店应用的图标不在 exe 里，而在包的 AppxManifest.xml（<uap:VisualElements Square44x44Logo=.../>）中，由 Shell 按需提供。现有三条路径都无法稳定取得：SHGetFileInfo 走图标缓存（易白屏）、ExtractIcon 只认 exe/dll/ico 文件、QFileIconProvider 分辨率过低且同样依赖缓存。

2. 本地实测（开发机桌面）

桌面 46 个快捷方式中 12 个带 AppUserModelID 属性，均为 MSIX 打包的桌面应用（Antigravity IDE / Clash Verge / Obsidian / Postman / VS Code / QQ / 剪映 等），其 TargetPath 仍是真实 exe；典型 UWP（计算器、照片、Store 等）快捷方式目标为 explorer.exe shell:Appsfolder\<AUMID> 或纯 AUMID，当前桌面暂无此类。

因此兼容需覆盖两种形态：

  • 带 AUMID 的 MSIX 桌面应用（exe 存在但图标资源缺失时同样拿到通用图标）
  • 纯 UWP 应用（无 exe 路径，shell:Appsfolder\<AUMID>）

AUMID 示例：Microsoft.WindowsCalculator_8wekyb3d8bbwe!App（格式 = PackageFamilyName!AppId）。

3. 兼容方案（三层）

L1 · 主路径：IShellItemImageFactory

对任意 Shell 项（.lnk / exe / 文件夹）用 SHCreateItemFromParsingName 创建 IShellItem，再调 IShellItemImageFactory::GetImage(size, SIIGBF_BIGGERSIZEOK | SIIGBF_ICONONLY) 取 HBITMAP 转 QPixmap。Shell 原生解析快捷方式目标，高清、不依赖文件路径、不依赖图标缓存，是 Win10/11 上社区公认最可靠路径。对普通 exe 可统一走此路，简化链路。

// 伪代码（SysInfoUtil 新封装 LoadShellItemIcon）
CComPtr<IShellItem> item;
SHCreateItemFromParsingName(lnkPath, nullptr, IID_PPV_ARGS(&item));
CComPtr<IShellItemImageFactory> factory;
item->QueryInterface(IID_PPV_ARGS(&factory));
SIZE size = { side, side };
HBITMAP hbm = nullptr;
factory->GetImage(size, SIIGBF_BIGGERSIZEOK | SIIGBF_ICONONLY, &hbm);
QPixmap pix = QtWin::fromHBITMAP(hbm, QtWin::HBitmapAlpha); // 注意：有黑边风险，须走第 4 节 T6 专用转换
DeleteObject(hbm);

L2 · 兜底：AUMID + AppxManifest（L1 失败/空白时）

  1. 读快捷方式属性 PKEY_AppUserModel_ID（SHGetPropertyStoreFromParsingName 或 IShellLink）拿 AUMID；若 TargetPath 含 shell:Appsfolder\ 则直接取其后缀。
  2. AUMID 取 ! 前部分 = PackageFamilyName，查注册表 
    HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\CurrentVersion\AppModel\Repository\Packages\<PFN>
    取值 PackageRootFolder（安装目录）与 AppxManifest（清单路径）。
  3. 解析 AppxManifest.xml 的 <uap:VisualElements Square44x44Logo="Assets\..." Square150x150Logo="..." /> 相对路径，按目标尺寸选择对应资源目录（scale-100/125/150/200/400）下的 PNG 读取。

注意：安装目录 C:\Program Files\WindowsApps 默认 ACL 受限（TrustedInstaller），部分机器普通进程读不到清单。优先 L1；L2 仅作为 L1 空白时的兜底，读不到就回退现有逻辑，不要阻塞图标加载。

L3 · 可选：WinRT PackageManager 全枚举

若未来需要"列出所有已装商店应用"（如组件系统里的应用启动器），引入 C++/WinRT Windows.ApplicationModel.PackageManager 枚举包并读图标。桌面图标场景不需要，本方案不实现。

4. 黑边与清晰度问题（2026-10-14 回归分析）

现象：按本方案实现后，图标出现黑边（黑色描边/halo），且图标模糊不清晰。

结论：实现存在 3 个根因叠加：HBITMAP alpha 语义错配、无 ICONONLY 回退引入缩略图背景、普通文件/文件夹被全量切到 L1。修复见任务 T6-T9。

4.1 根因 1：HBITMAP alpha 语义错配（黑边主因）

SysInfoUtil.cpp:568 用 QtWin::fromHBITMAP(hBmp, QtWin::HBitmapAlpha) 转换，Qt 按 预乘 alpha（Format_ARGB32_Premultiplied）解读。而 IShellItemImageFactory 在 ICONONLY 模式下对不同 Shell 项返回的 HBITMAP alpha 语义不一致：部分返回 straight alpha，部分为 24bpp 无 alpha（DDB）。straight 数据被按预乘解读 → 半透明边缘 RGB 残留 → 黑色 halo。

4.2 根因 2：无 ICONONLY 回退引入缩略图背景

SysInfoUtil.cpp:560 / :564 的失败回退不带 SIIGBF_ICONONLY → 进入缩略图模式。文件夹/图片文件会返回带白色（或黑底）背景的缩略图矩形 → 明显黑/白边。此回退对文件夹图标尤其致命。

4.3 根因 3：普通文件/文件夹被全量切到 L1（"都不清晰"放大器）

ListItemData.h:448-449 对所有图标先走 LoadShellItemIcon。普通 exe 的图标源小（16/32/48px），被 GetImage 请求 96/256 后用 GDI 拉伸 → 模糊；文件夹走根因 2 的缩略图分支 → 背景块。改造前这两类走 SHGetFileInfo/ImageList（256px 原生、有 alpha）与 GetShellThumbnail+sanitize（专门处理过黑底），都不该被替换。

4.4 清晰度根因：请求尺寸超出图标源

GetImage(sz=96/256) 而 UWP 图标源仅 44/48px（Square44x44Logo），Shell 用 GDI 放大 → 糊。Qt 的 SmoothTransformation 平滑缩放远好于 GDI StretchBlt；UWP 的 scale-200/400 PNG（88/176px）是原生清晰来源。

4.5 修复要点（对应 T6-T9）

  • T6：LoadShellItemIcon 改为专用转换：GetObject 查位深；32bpp 且存在半透明像素时逐像素检测 r>a || g>a || b>a（straight 误读特征）→ demultiply + clamp；无 alpha 按 NoAlpha 处理。请求尺寸 min(side, 64)，返回后由 Qt 平滑缩放到档位。删除 :560/:564 两个无 ICONONLY 回退。
  • T7：ListItemData.h:448-449 收敛 L1 范围：仅 .lnk / .appref-ms / UWP 走 L1/L2；普通文件保留 SHGetFileInfo/ImageList，文件夹保留 GetShellThumbnail + sanitizeFolderPreviewMatte。
  • T8：LoadUwpAppIconFromAumid 反转优先级：先解析 manifest 读 PNG（真 alpha、高分辨率、无黑边），shell:Appsfolder 仅作失败兜底；findBestImageCandidate 的 scale 优先级按 side 参数调整（side≥176 → scale-400 优先；≥88 → scale-200；否则 scale-100/150）。
  • T9：回归验证（见第 7 节）。

7. 验证方式

  • 黑边检查：任意图标放大 200% 截图，四角与边缘无黑色描边；半透明边缘（如 UWP 圆角 logo）背景干净。
  • 清晰度：96px 档图标源≥96px 时原生清晰（不模糊）；小源图标由 Qt SmoothTransformation 缩放而非 GDI 拉伸。
  • 形态覆盖：桌面 12 个 AUMID 快捷方式（MSIX 桌面应用）+ 手动固定计算器/照片等到桌面（纯 UWP）→ 两类图标均正确显示且无黑边。
  • 回归：普通 exe 快捷方式、文件夹、图片文件图标与改造前一致（对比截图）；文件夹无白/黑底背景块。
  • 异常：指向已卸载 Store 应用的快捷方式显示不崩溃、回退通用图标；无句柄/内存增长。
  • 缓存：结合 docs/LinDesk_ListView_Memory_Review.html 的验证清单，确认新图标 key 参与上限与失效机制。

8. 风险与注意

  • WindowsApps ACL：L2 读注册表路径在部分机器可能因目录权限失败，属预期，回退即可。
  • 图标缓存：不要依赖 SHGetFileInfo 为 Store 应用提供图标（Win11 缓存损坏会整片变白，微软已知问题）——这正是换 L1 的原因。
  • 线程与 COM：IShellItemImageFactory 调用要求 COM 初始化；图标加载目前主线程执行，注意封装内处理。
  • 性能：L1/L2 仅首次调用开销，结果进缓存；不要在渲染热路径重复解析 AUMID。
  • Win7 兼容：IShellItemImageFactory 最低 Vista，项目 Win10/11 目标不受影响。
  • HBITMAP alpha：IShellItemImageFactory 返回位图的 alpha 语义不稳定（社区已知），不要直接信任 HBitmapAlpha 转换，一律走 T6 的专用转换。
