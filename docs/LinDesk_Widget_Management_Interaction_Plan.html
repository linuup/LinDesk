LinDesk 组件管理 HTML 化与桌面交互协同重构方案

作者：LinDesk Architecture Team 版本：1.0.0 状态：方案审定与实施设计 日期：2026-10-28
核心设计原则： 1. 表现层全面拥抱 Web：组件管理从 C++ QWidget 纯自绘代码解放，采用本地轻量 HTML/SPA，极大减轻维护包袱；
2. 核心服务稳定驻留 Qt：安装解压、权限校验、进程生命周期由 C++ 稳定支撑，前后端通过异步 IPC 契约通信；
3. 桌面分层协同交互：桌面图标（前景优先）、小组件（局部独占感应）、全屏壁纸（背景共享跟随），彻底消灭交互冲突。

一、 组件管理页面 HTML 化方案

1.1 现状与痛点定位

目前 SettingUI.cpp 已累积超过 6,000 行 C++ 代码。其中“官方小组件”、“小组件市场”、“已安装列表”等视图完全使用纯 C++ 原生 QWidget、QListWidget、自绘卡片控件与手工拼接的 QSS 样式表进行堆砌：

  • 开发与调试成本极高：调整界面内边距、字体排版或卡片阴影，均需要重新编译整个庞大的 C++ 工程；
  • 视觉表现力受限：流式栅格布局（Flex/Grid）、骨架屏加载动效、平滑折叠展开等现代化 Fluent UI 体验在 QWidget 中开发极其繁琐；
  • 代码严重臃肿：包含大量 createSettingsLinWidgetRow、事件过滤器与杂乱的尺寸计算逻辑。

1.2 架构设计：CEF 独立子进程承载

项目已彻底集成 Chromium Embedded Framework (CEF OSR)，具备完备的 LinDeskSubprocess 独立渲染子进程与 IPC 消息管道。管理页面转为 Web 方案具有天然优势：

维度传统 QWidget 方案CEF HTML 管理页方案
代码组织C++ 视图与业务紧耦合（数千行 QWidget 代码）关注点分离：C++ 只保留约 200 行 RPC 桥，UI 完全由 Web 单页呈现
进程稳定性界面解析或崩溃直接连带桌面主进程退出沙箱隔离：页面在独立渲染子进程运行，崩溃不影响桌面
调试效率反复改代码、增量编译、启动断点开箱即用 DevTools：实时 DOM 审查、样式热更新
输入法与性能需处理 Qt 控件嵌套事件原生硬件加速：独立窗口模式下输入法（IME）与高刷滚动原生丝滑

二、 桌面壁纸交互与拖拽框选协同方案

2.1 冲突根本原因剖析

全屏动态壁纸（如卡冈图雅黑洞、粒子星空）具有 interactive: true 交互能力。在当前实现中：

  • 当鼠标在桌面空白处按下时，ListView::mousePressEvent 判定该位置被全屏壁纸命中；
  • 由于执行了 forwardMouseEvent(event) 且直接 event->accept(); return;，导致事件链在此处被彻底截断；
  • ListView 用于拉出蓝色半透明框选矩形的 SelectArea 逻辑完全没有机会执行，导致“桌面空白处无法框选图标”。

2.2 解决方案：延迟拖拽判定（Cooperative Routing 协同分发）

核心原则是：“背景共享，前景优先”。将独占式拦截改为基于位移阈值的协同决策：

事件阶段针对全屏动态壁纸的行为针对桌面 ListView 的行为
鼠标移动 (MouseMove)
无按键按下		 无阻碍实时转发，保证壁纸视差倾斜、粒子跟随、黑洞引力光晕 100% 丝滑跟踪。 正常维护图标悬停状态。
鼠标按下 (MousePress)
左键点击空白处		 即时发送给壁纸，触发点击涟漪/引力波爆发动画。 不截断事件。记录按下起始点 m_dragStartPos = event->pos()，置位 PendingSelect。
按住拖动 (MouseMove)
按住左键移动		 当位移 > 6px 时，向壁纸发送虚拟 Release，退出壁纸按压。 判定为用户明确想框选图标，立即唤起 SelectArea 蓝色框选虚线框。
鼠标松开 (MouseRelease)
位移未超阈值		 正常发送松开事件给壁纸。 判定为纯单击空白处，取消当前所有选中的文件图标。

三、 小组件尺寸修改与交互控制方案（基于 Ctrl 组合键的高效协同方案）

3.1 核心设计理念：为什么坚持采用 Ctrl 方案？

LinWidget 小组件本质是基于 CEF OSR 离屏渲染的富 Web 容器，其内部包含了复杂的 HTML5/CSS3 交互元素（如可拖动的滑块、靠边的滚动条、全宽卡片、边缘按钮及悬浮气泡）：

  • 避免 Web 内部事件被粗暴抢占：若在无修饰键下强行将边缘 8~10px 划归为宿主缩放区，会导致组件内部靠近边缘的按钮、表单输入、关闭图标、滚动条无法正常点击与拖动；
  • 明确的操作意图（Intent Separation）：通过按住 Ctrl 键作为桌面宿主管理修饰符，将“组件内部交互（Web UI）”与“桌面布局编排（Host Layout）”清晰隔离，彻底消除误触；
  • 全能协同控制：按住 Ctrl 键时一举打通“8 方向边缘智能缩放”、“内部拖拽自由移动”以及“鼠标滚轮等比平滑缩放”，配合右键预设菜单，构成完备的尺寸控制生态。

3.2 方案设计：三层递进的尺寸控制体系

① 按住 Ctrl + 边缘智能缩放光标与 8 方向控制

  • 边缘自适应判定：当鼠标光标悬停在小组件四周边缘（10px 判定区）并检测到按住 Ctrl 时，自动切换为双向缩放光标（SizeHorCursor、SizeVerCursor、SizeFDiagCursor、SizeBDiagCursor）；
  • 内部自由位移：鼠标悬停在小组件内部并按住 Ctrl 时，光标切换为全向移动十字光标（SizeAllCursor），左键拖动可自由平移小组件位置，释放时自动吸附屏幕边界并保存坐标；
  • Fluent 强调色视觉辅助反馈：按住 Ctrl 悬停或拖拽时，宿主外层实时绘制 2px Fluent Accent 高亮描边、8 个控制点调节手柄与顶部实时尺寸胶囊徽章（如 360 × 200），松开即自然淡出。

② 按住 Ctrl + 滚轮平滑等比缩放

  • 鼠标光标悬停在小组件上方并按住 Ctrl 时，滚动鼠标滚轮触发宿主级平滑等比缩放（步进约 ±8%）；
  • 以当前鼠标坐标为中心锚点自适应缩放，拦截事件避免穿透给 CEF 导致网页滚动；尺寸严格受 Manifest 最小/最大约束和屏幕边界保护。

③ 右键快捷规格（免按键一键预设）

为无需按键的场景提供更快速的标准网格化规格，右键单击小组件弹出专属上下文菜单：

  • 小卡片 (1×1)：标准 200 × 200 px，适合时钟、微型天气卡；
  • 标准条状 (2×1)：标准 360 × 200 px，适合便签、待办清单、双指标监控；
  • 大卡片 (2×2)：标准 400 × 300 px，适合综合仪表盘、日历视图；
  • 全宽展板 (Full Width)：标准 540 × 320 px，适合复杂媒体看板或股票图表；
  • 内置“重新加载小组件”、“小组件设置...”与“关闭并移除组件”一站式管理。

④ 桌面小组件编辑/锁定模式

  • 桌面右键菜单提供“编辑小组件 (Edit Widgets)”模式；
  • 进入编辑模式时，所有小组件显示轻量遮罩层、四角缩放圆点、顶部居中拖动条、右上角关闭按钮；
  • 退出编辑模式后全部锁定，彻底杜绝日常使用过程中的任何误拖拽与误缩放。

⑤ CEF OSR 视口动态重绘与持久化

// 缩放生效流程：
1. 鼠标拖拽拉伸结束 -> ListView 获得新尺寸 QSize(newW, newH)

四、 壁纸工坊与可视化配置编辑器方案 (Wallpaper Studio)

4.1 人机工学定位与双轮驱动架构

在 LinDesk 动态壁纸生态中，定位清晰划分为两个闭环层级：

  • AI 开发者层（骨架与特效）：负责生成高复杂度的动态引擎、3D 粒子流、视差交互模板或 Canvas 着色器代码；
  • 终端用户层（资产装配与个性化）：广大非编程用户拥有极强烈的诉求，希望零代码自由更换本地收藏的精美壁纸图片、4K 动图或 MP4/WebM 视频剪辑。

传统的“弹出文件选择对话框”方案存在致命缺陷：用户选完后无法感知缩放拉伸是否失真、是否出现黑边、视频声音过大、以及主体过于明亮导致桌面图标文字完全无法辨识。因此，必须提供一个类似 Wallpaper Engine / Lively Wallpaper 的可视化配置编辑器——“壁纸工坊 (Wallpaper Studio)”。

4.2 界面布局与交互设计（Web 单页架构）

得益于表现层已拥抱 CEF 独立窗口模式，壁纸工坊直接采用基于现代 HTML5 + Flex/Grid 的双栏 Web 视图：

五、 边界防坑与工程实施细则 (Critical Implementation Rules)

4.1 右键绝对保护原则 (Right-Click ContextMenu Protection)

核心红线：全屏动态壁纸严禁接收任何右键鼠标事件（Qt::RightButton）。
  • 穿帮风险：如果右键被无差别透传到底层 CEF 壁纸，Chromium 会弹出原生的网页右键菜单（“查看网页源代码”、“检查元素”、“重新加载”），破坏桌面原生宿主感；
  • 隔离实现：ListView::mousePressEvent 与 mouseReleaseEvent 遇到右键时，100% 由 Qt 桌面消费并唤起原生 Win11/Qt 桌面上下文菜单，壁纸仅接收 MouseMove（无按键悬停）和 LeftButton（左键按下与释放）。

4.2 高分屏 DPI 物理像素精确映射 (HiDPI Coordinate Normalization)

痛点现象：笔记本和 4K 屏普遍开启了系统缩放（125%、150%、200%）。Qt 事件返回的是逻辑坐标，而壁纸 Canvas 为保证清晰度采用的是 4K 物理像素。若直接透传，会导致“鼠标点在屏幕正中，引力波涟漪却在左上角炸开”的“隔空点物”偏差。
  • 解决方案：鼠标事件坐标发往 CEF 之前，必须经过 devicePixelRatio() 换算，确保鼠标指针尖端与壁纸特效落点在物理像素层面绝对严丝合缝：
    const QPoint physicalPos = event->pos() * window()->devicePixelRatioF();

4.3 前台单例保活与零时延唤醒 (Keep-Alive & Instant Wakeup)

体验目标：用户在设置中心切换 Tab 时，0 毫秒秒切，无白屏闪烁，保留用户搜索和滚动位置。
  • 单例保活：管理页 CEF Browser 实例在首次创建后常驻内存，切到其他 Tab 时仅调用 hide() 并暂停定时重绘，避免每次重新加载 URL 的 300ms 闪白；
  • 静默唤醒：再次切回该页时立即 show()，同时 Qt 通过 IPC 发送 page_activated 广播，前端仅按需静默同步最新的组件启停状态，界面无任何跳变与重载感。

4.4 小组件尺寸硬性约束保护 (Hard Geometry Constraints)

  • 组件包 manifest.json 必须配置硬性边界参数：minWidth, minHeight, maxWidth, maxHeight；
  • 桌面缩放逻辑中强制施加 qBound(min, val, max) 约束，严防组件被缩至 0 像素黑点或拉扯至超大分辨率挤爆显存。
