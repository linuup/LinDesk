LinWidget 协议与组件开发规范

版本：1.0.0 适用环境：Qt 5.15+ / CEF OSR Windowless 读者：小组件开发者、AI 编程代理、底层架构师
小组件体系导航提示：本篇为底层通信协议与开发手册。有关组件系统架构、沙箱安全与市场方案请参阅 组件平台方案；有关组件管理 SPA 页面与全屏壁纸框选协同请参阅 组件管理与交互方案。

1. 架构总览 (Architecture Overview)

LinDesk 组件系统采用 单进程 · 动态加载 · 离线画布合成 (CEF OSR Windowless) 架构：

  • 主程序 (LinDesk.exe)：零静态 CEF 链接，仅在需要时通过动态库桥接接口 (LinWidgetRuntimeBridge) 动态加载 LinWidgetRuntime.dll。
  • 组件运行时 (LinWidgetRuntime.dll)：宿主 Chromium Embedded Framework (CEF)、管理 OSR 离线渲染浏览器实例、执行安全沙箱策略并处理双向 IPC 消息。
  • 桌面画布合成 (LinWidgetCanvasWidget)：将各组件实例与动态壁纸的 BGRA 渲染帧，直接绘制到 Windows 桌面图层画布，与原生图标完美混流。
  • 数据隔离约束：组件系统只读写 LinWidgets/、LinWidgetsData/ 与 LinWallpapers/，严禁触碰或修改主桌面持久化数据文件 (data.dat / data.json)。

2. 组件包规范与 Manifest 规范 (Package & Manifest)

每个小组件为一个独立文件夹（或 .zip 压缩包），包根目录下必须包含 manifest.json：

2.1 目录结构

MyWidget/
├── manifest.json       # 组件元数据与权限声明（必须）
├── icon.png            # 组件图标（推荐 128x128 PNG）
├── index.html          # 入口 HTML 页面
├── style.css           # 样式表
└── script.js           # 逻辑脚本

2.2 manifest.json 字段规范

{
  "id": "com.example.clock",
  "name": "极简时钟",
  "version": "1.0.0",
  "author": "LinDesk Community",
  "description": "半透明毛玻璃桌面时钟组件",
  "icon": "icon.png",
  "role": "widget",
  "type": "html",
  "entry": "index.html",
  "width": 320,
  "height": 140,
  "minWidth": 160,
  "minHeight": 100,
  "maxWidth": 640,
  "maxHeight": 480,
  "transparent": true,
  "resizable": true,
  "autoLoad": true,
  "multiInstance": false,
  "permissions": [
    "storage",
    "desktop"
  ],
  "intent": {
    "prompt": "创建一个带有暗黑毛玻璃质感、秒针呼吸灯效果的桌面时钟",
    "ai_engine": "Claude-3.7-Sonnet",
    "created_at": "2026-10-14T01:30:00Z"
  }
}

核心字段说明

字段类型必填默认值说明
idstring是-唯一标识符，小写字母、数字及点号（如 lindesk.clock）
namestring是-组件显示名称
versionstring是1.0.0语义化版本号（X.Y.Z）
rolestring否"widget"角色："widget"（普通组件）或 "wallpaper"（全屏动态壁纸）
entrystring否"index.html"包内入口页面相对路径
width / heightnumber是-初始宽度与高度（像素，仅 role="widget" 生效）
transparentboolean否true是否支持 Alpha 透明通道渲染
resizableboolean否true是否允许用户拖拽边角手柄缩放尺寸
permissionsarray否[]申请特权数组："storage", "desktop", "network"
intentobject否{}记录 AI 辅助生成的原始需求与引擎信息，供增量修复参考

3. 双向通信桥接机制 (Bridge Protocol)

小组件运行在独立的 Chromium 隔离沙箱环境中，通过统一的 Bridge 协议与 C++ 宿主双向通信：

3.1 组件向宿主发送请求 (Outbound)

组件支持两种等价的消息发送通道：

推荐方式 A：原生 Bridge 拦截通道 (零开销)

function sendHostMessage(message) {
  fetch('http://linwidget.bridge/postMessage', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(message)
  }).catch(function (err) {
    console.error('Bridge postMessage error:', err);
  });
}

兼容方式 B：Standard postMessage

window.parent.postMessage(message, '*');

3.2 宿主向组件推送消息/响应 (Inbound)

window.addEventListener('message', function (event) {
  const msg = event.data;
  if (!msg || typeof msg !== 'object') return;
  console.log('Received from host:', msg.type, msg);
});

4. 标准协议消息面字典 (Message Schema Reference)

4.1 系统信息 API (SystemInfo)

所需权限：desktop

4.1.1 获取即时快照 (system_info_snapshot)

// 请求
{ "type": "system_info_snapshot", "requestId": "req_101", "action": "snapshot" }

// 宿主响应 (systemInfoResponse)
{
  "type": "systemInfoResponse",
  "requestId": "req_101",
  "ok": true,
  "data": {
    "cpu": { "usagePercent": 14.5, "coreCount": 16, "brand": "13th Gen Intel Core i7" },
    "memory": { "totalBytes": 34359738368, "usedBytes": 17179869184, "usagePercent": 50.0 },
    "battery": { "hasBattery": true, "percent": 98, "charging": true }
  }
}

4.1.2 订阅周期推送 (system_info_watch)

// 订阅
{ "type": "system_info_watch", "requestId": "req_102", "watchId": "cpu_watcher_1", "action": "watch", "intervalMs": 1000 }

// 宿主推送 (systemInfoUpdate)
{ "type": "systemInfoUpdate", "watchId": "cpu_watcher_1", "data": { ... } }

// 取消订阅 (system_info_unwatch)
{ "type": "system_info_unwatch", "requestId": "req_103", "watchId": "cpu_watcher_1", "action": "unwatch" }

4.2 本地持久化存储 API (Storage)

所需权限：storage。数据独立保存在 <userData>/LinWidgetsData/<widgetId>/storage.json 中，绝对隔离。

// 存入键值
{ "type": "storage_set", "requestId": "req_201", "action": "set", "key": "theme_mode", "value": "dark" }

// 读取键值
{ "type": "storage_get", "requestId": "req_202", "action": "get", "key": "theme_mode" }

// 响应
{ "type": "storageResponse", "requestId": "req_202", "ok": true, "value": "dark" }

// 删除与清空
{ "type": "storage_remove", "requestId": "req_203", "action": "remove", "key": "theme_mode" }
{ "type": "storage_clear", "requestId": "req_204", "action": "clear" }

4.3 动态壁纸专用 API (Wallpaper)

仅对 manifest.role = "wallpaper" 的壁纸组件生效。

// 弹出系统文件选择框选择本地视频或图片
{ "type": "wallpaper_set_source", "requestId": "req_301", "dialog": true }

// 宿主响应：注入本地媒体
{ "type": "wallpaper_source_changed", "requestId": "req_301", "ok": true, "sourcePath": "D:/Wallpapers/cyberpunk.mp4" }

// 切换内置主题预设 (aurora / twilight / deepblue)
{ "type": "wallpaper_set_preset", "requestId": "req_303", "preset": "twilight" }

媒体加载规范：选定本地媒体文件后，通过 linwidget://wallpaper:<id>/_media?path= 自定义协议直接赋予 <video src="...">，突破 Chromium 本地文件访问拦截。

4.4 窗口与视口控制 API

// 组件主动请求变更位置与尺寸
{ "type": "widget_geometry_changed", "x": 100, "y": 120, "width": 360, "height": 200 }

// 请求打开宿主对应组件的设置面板
{ "type": "open_widget_settings" }

5. 权限沙箱与安全模型 (Security & Sandbox)

  • 资源协议隔离 (linwidget://)：所有组件页面及内部静态资源必须通过 linwidget://<instanceId>/<relativePath> 加载。宿主执行严密的目录穿越检测，拦截任何跳出组件目录的非法请求。
  • 外网权限拦截 (network)：未在 manifest.permissions 中声明 "network" 的组件，所有外发网络连接在 CEF OnBeforeResourceLoad 层直接拦截并返回 RV_CANCEL。
  • 输入穿透检测：鼠标点击组件像素 Alpha < 10 的透明区域时，事件自动穿透给桌面原生图标，确保原生桌面操作零受阻。

6. 开发者工具与 AI 增量修复闭环

调试面板内置 「导出诊断包」 功能：

  • 脱敏保护：自动将用户绝对路径替换为 <USER_HOME>；
  • 诊断包内容：完整 Manifest 元数据、当前运行时状态（尺寸、Z 序、已授予特权）、最后 200 行控制台异常日志；
  • 闭环修复模式：组件异常时，将诊断包直接提交给 AI 编程助手，即可在保持原有组件结构的前提下完成增量精准修复。
