LinDesk 组件系统方案（单进程 · 组件包动态加载）

读者：antigravity / 开发者 性质：组件平台打磨 + 与主程序集成任务书 范围：组件系统（linwidget + CEF OSR + 壁纸）在主程序进程内运行、组件包独立动态加载 更新：2026-10-13

1. 背景与定位

LinDesk 的差异化价值在于 HTML 组件系统：任何 HTML/CSS/JS 内容都能成为桌面组件。组件系统运行在主程序进程内（单进程），但组件包保持独立：用户动态下载/放置组件包即加载，不捆绑安装——主程序安装包只含组件运行时（CEF 等基础），不预装任何业务组件。

决策记录（2026-10-13）：放弃多进程方案。此前设计的 LinWidgetHost.exe 独立进程方案（见 _backup/LinDesk_Widget_Host_Plan-v1.html）已否决：CEF 本身是多进程架构（渲染进程崩溃不会拖垮主程序，已有 handleBrowserCrashed 自动重建），额外进程隔离收益边际小；而跨进程显示/传帧/事件回传引入的复杂度远大于收益。组件系统的"独立"由组件包级动态加载实现，不由进程隔离实现。

本方案把组件系统从"能用的容器"打磨成"可生长的平台"，并明确与主程序的集成边界——组件包如何动态加载、运行时如何渲染合成、交互如何路由、数据如何归属。

核心开发者是 AI 而不是人（已拍板）：SDK、TS 类型、API 文档站点等"人向"工具一律不做。平台的三项职责是——

  • 给 AI 清晰的规则：协议规范极简固定、示例组件可参考；
  • 给 AI 及时的反馈：校验器报错、运行时日志/异常可导出、意图可保留；
  • 给 AI 的产物安全兜底：权限最小化、危险代码拦截、资源限制。

视觉自由（已拍板）：不做设计令牌、不做视觉规范强制。组件长什么样由作者和用户决定，平台只管功能、安全与迭代闭环。

2.3 组件与主程序的接口面（同进程）

  • 运行时消息协议：handleRuntimeMessage（WidgetManager.cpp:1906）收敛固化：geometry、settings、system_info、storage、实例管理（create/list/close）、error——同进程信号/回调直连，无 IPC 封装；
  • 事件信号：保留现有 widgetError / widgetLaunched / widgetStopped / widgetSettingsRequested / widgetGeometryChanged 信号，主程序 UI（设置页、右键菜单、命中测试）直接连接；
  • 输入注入：ListView 事件 → WidgetManager forward*Event → CefOsrBrowserInstance（现有链路，无跨进程跳转，延迟最低）；
  • 高频数据：system_info 订阅推送、console 流全部在主程序进程内闭环，直接进调试面板日志查看器。

2.4 主程序集成设计（组件包动态加载）

  • 组件目录扫描：启动时扫描 <userData>/LinWidgets/ 下每个组件包目录 → 读取 manifest.json → 校验器 lint → 注册进 registry.json；目录不存在则为空态（无组件不报错）；
  • 动态加载/卸载：新增包目录 → 即时校验注册并可启动实例；删除包目录/卸载 → 停止实例、仅移除代码，storage 数据保留；无需重启主程序（加载器监听目录变化或手动刷新）；
  • 入口显隐：右键菜单组件项、设置页组件区按"是否已装组件/是否可用"动态显示；零组件安装时入口正常存在并引导去下载；
  • 崩溃恢复：单个组件 OSR 实例崩溃 → handleBrowserCrashed 自动重建（60s 内 3 次熔断）；桌面其他功能不受影响（CEF 多进程隔离）；
  • 版本兼容：组件包 manifest 声明 runtimeVersion / protocolVersion；不兼容 → 加载器拒绝并提示更新组件包或主程序；
  • 设置页组件区：组件列表（名称/版本/启用状态）+ [下载组件]（Releases 直链）+ [检查更新] + [卸载] + [打开组件管理]。

2.5 目录与数据归属

路径用途读写方

3. 前置地基：CEF 四项技术缺口（P0，组件系统内先行）

打磨建立在渲染栈完整之上。以下四项是当前 CEF 迁移遗留的功能缺口，必须先补齐（全部在组件系统/主程序进程内实现），否则作者层（运行时反馈）与运行层（权限沙箱）无从谈起。

缺口现状（代码依据）影响实现要点
IME 候选窗口CefOsrBrowserInstance.cpp:487-513 有 ImeCommitText / ImeSetComposition / ImeCancelComposition，但 OnIMECandidateCountToQuery / OnIMECompositionRangeChanged 等回调未实现中文输入候选框/组合框不显示，输入体验不完整补 CefOsrRenderHandler 的 IME 回调，参考 cefclient 的 osr_ime_handler_win.cpp
本地资源 scheme组件以 file:// 直载（WidgetManager.cpp:737/809/1179），无自定义 scheme、无 GetResourceHandler跨目录资源、组件内 fetch 本地数据受 Chromium 同源/CORS 限制，现在"能用但脆"实现 linwidget:// 自定义 scheme，按组件包目录映射；CSP 头随 scheme 响应统一注入（不单独立项）

4. 作者层：AI 开发闭环（主程序内）

AI 不需要 SDK，需要"规范 + 示例 + 校验器 + 反馈"。作者层的五个环节构成闭环：AI 读规范与示例 → 生成组件包 → 校验器报错 → AI 按错误修 → 安装运行 → 诊断导出再迭代。校验器与诊断包运行在主程序（安装/调试入口在组件管理窗口与调试面板）。

4.1 协议规范（定稿）

  • 以现有 handleRuntimeMessage（WidgetManager.cpp:1906）已支持的消息面为准，收敛固化，不新增无谓类型：geometry、settings、system_info、storage、实例管理（create/list/close）、error 等；
  • 字段命名统一 snake_case；每类消息配一个请求/响应 JSON 示例；
  • 错误码固定 3 个：OK / DENIED（权限拒绝）/ INVALID（参数或格式错误），拒绝与失败必须显式返回错误码而非静默；
  • 文档短到能整段放入 AI 上下文，作为组件生成的输入素材。

4.2 示例组件仓库

  • GitHub 开源：官方最小组件模板 + 3 个完整参考实现（Clock / Notes / Todo）；
  • 既是 AI 生成的 few-shot 素材，也是人工调试的对照物；
  • 仓库同时承载组件索引（见第 5 节）。

4.3 组件校验器

  • 安装时 lint：manifest 字段完整性、权限是否声明、HTML/JS 语法；
  • 输出结构化错误清单（位置 + 原因 + 修法），可直接反馈给 AI 迭代；
  • 危险模式扫描分级：error 确定有害（eval + 远程代码执行、远程脚本注入）；warning 可疑（内联事件、超大包、未声明权限却出现外部请求）；
  • 与权限模型联动（防误伤）：外部请求类代码只有在"manifest 未声明对应权限"时才判为错误——Weather 组件合法请求天气 API 不因出现外联 URL 被拦。

4.4 运行时反馈与诊断包

  • console / 未捕获异常 / 网络请求记录转发到调试面板日志查看器（依赖 3.3 缺口）；
  • 调试面板提供一键导出诊断包：组件 manifest + 运行日志 + 异常 + 最近错误，格式化为可直接粘贴给 AI 的文本；
  • 脱敏约束：诊断包只含组件自身数据，不包含用户桌面其他信息。

4.5 意图保留

  • manifest 记录生成意图（原始需求描述 + AI 引擎/版本）；
  • 组件出问题时，把"旧包 + 意图 + 新需求 + 诊断包"四件套喂给 AI，做增量修复而非推倒重写，成功率更高、结果更稳定。

4.6 生成入口（远期可选，不做承诺）

  • 主路径（现在就用）：用户在任意 AI 工具（Cursor / 豆包等）里按规范 + 模板生成组件包，LinDesk 负责校验与安装；
  • 远期可选：调试面板内"描述式生成"（调大模型 API 返回组件包），仅作探索，不作为本方案交付项。

5. 市场层：组件发现与更新（主程序执行）

复用此前已完成设计的 GitHub 更新方案思路（客户端请求 GitHub Releases API + gh CLI 发布 + digest 免手算）同构实现，不引入新基建。下载/校验/安装/卸载由主程序执行，设置页组件区提供入口与安装状态。

能力设计要点
组件索引GitHub 仓库根目录 index.json：组件 id / 名称 / 简介 / 图标 / 最新版本 / 包下载 URL与组件示例仓库合并维护，版本号由发布流程统一管理（避免 AI 乱写版本）
在线安装 / 卸载拉取 index.json → 展示列表 → 下载 .lw 组件包 → SHA-256 校验 → 解压到组件目录 → 注册校验失败拒绝安装并提示原因；卸载保留用户数据（storage 按组件隔离，卸载仅移除代码）
组件更新启动时（或手动）对比已装版本与索引最新版，提示一键更新复用 UpdateChecker / compareVersions 数字语义；更新前备份旧包可回滚
离线降级GitHub 不可达时组件照常运行仅不提示更新；安装/更新按钮置灰并说明原因，不做静默失败
来源信任哈希校验 + 来源白名单（官方仓库固定）第三方索引暂不支持，避免供应链风险

6. 运行层：权限、推送、生命周期、沙箱（主程序内）

6.1 权限模型（收敛，避免过度设计）

  • 保持三类为主：network（外联请求）/ storage（组件数据读写）/ desktop（桌面集成：拖放、文件、快捷键预留）；可选扩展 clipboard；
  • 不做存储读写分离：拆"读/写"两个权限增加协议复杂度、收益低，组件作者与 AI 都更难理解；
  • 安装时最小化授予：只授予 manifest 声明且校验器通过的权限。

6.2 运行时申请流

  • 组件首次调用未授权权限时，主程序弹窗询问；请求挂起等待用户决策，避免组件无限重试；
  • 拒绝后该 API 返回 DENIED 错误码（协议可见，AI 能据此修）；
  • 同组件同权限记住选择，不重复弹窗；用户可在调试面板权限页随时撤销。

6.3 订阅-推送

  • system_info 在现有 request/response 基础上增加 subscribe / unsubscribe；
  • 推送按 1s 节流，组件挂起时不推送、恢复后补一帧；
  • 组件必须显式取消订阅，避免泄漏（组件销毁时平台强制清理）。

6.4 生命周期（定义要克制）

  • 挂起条件：窗口最小化 / 组件被显式隐藏时暂停渲染帧（OSR WasHidden）；不做窗口遮挡检测（桌面层级复杂、收益低）；
  • 内存压力时按 LRU 卸载挂起组件的 OSR 实例；恢复时重建实例 + 加载组件包 + 从 storage 恢复状态（成本明确：一次实例创建 + reload）；
  • 状态恢复依赖 layout.json（geometry，已有）与 storage（组件数据，已持久化）——不再设计额外的数据快照机制。

6.5 沙箱

  • 网络：OnBeforeResourceLoad 按 6.1 权限放行/拦截（补 3.4 缺口）；
  • CSP：随 linwidget:// scheme 响应统一注入，锁定远程脚本/外联字体等（随 3.2 缺口一并实现，不单独立项）；
  • 资源配额：组件存储上限（如 16MB），超限 API 返回 INVALID 并提示。

7. 体验层：设置、状态、交互（同进程）

8. 壁纸组件（role: wallpaper，桌面画布合成）

8.1 定位与设计原则

动态壁纸是组件系统内部的特殊组件类型（manifest.role: "wallpaper"），与普通组件共用包规范、CEF OSR 实例、消息桥、权限模型、Canvas 帧合成与注册表/调试面板入口。不做独立运行时，不复刻 WebView2 时代的 LinWallpaperWebViewRuntime。组件系统只有一种组件，role 只区分行为。渲染上，壁纸 = 全屏 CEF OSR 实例，帧由 CanvasWidget 合成进桌面画布（与普通组件同管道，层级最低）。

8.2 现状盘点（代码依据）

层现状结论
包格式manifest.role 默认 "widget"（LinWidgetTypes.h:24）；launchWidgetInstance 对 role=="wallpaper" 分流（WidgetManager.cpp:483-488，instanceId=wallpaper:{id}）→ startWallpaper格式已定义，运行时待实现
持久化filterWallpapers 按 role 过滤（WidgetManager.cpp:956），壁纸不落 layout.json，走独立壁纸配置（LinWallpapers/Enabled）隔离持久化已设计
绘制原 ListView::paintEvent 的 hasActiveWallpaper() 分支预留透明遮底（ListView.cpp:1303-1305）——壁纸激活时该遮底继续由 ListView 合成（遮系统壁纸底图），壁纸帧由 CanvasWidget 合成进桌面画布层级挂点保留在桌面画布合成（壁纸帧最先画）
运行时startWallpaper 返回 false + "not yet supported"（WidgetManager.cpp:2172）；activeWallpaperWidget() 返回 nullptr；load/saveWallpaperConfig 空实现唯一要补的核心

8.3 特殊化设计（与普通组件的六项差异）

维度普通组件壁纸组件实现要点
尺寸包内 width/height，可拖拽缩放= 桌面视口（桌面窗口客户区），不可拖拽geometry 绑定桌面尺寸，resize 跟随；不走 LayoutManager

生命周期可关可停单例（同时仅一个活动壁纸），启动自动恢复切换先停旧实例；load/saveWallpaperConfig 落地

9. 组件系统落地清单（组件包动态加载）

在现有单进程组件代码基础上，落地"组件包独立、动态加载"需要补的能力：

  1. 组件目录与加载器：扫描 <userData>/LinWidgets/<componentId>/ → 读 manifest → 校验（4.3）→ 注册进 registry.json → 可创建实例；监听目录变化支持热加载；
  2. manifest 注册表：记录组件 id / 版本 / role / 权限声明 / 启用状态 / 几何（现有 registry.json 结构扩展）；
  3. 动态启停：放置/安装组件包后即可启动实例；卸载 = 停实例 + 移除代码 + 保留 storage 数据；无需重启主程序；
  4. 入口：设置页组件区（组件列表 + 下载 + 检查更新 + 卸载）+ 右键菜单组件项按"已装组件"动态显示；
  5. 崩溃恢复：组件实例崩溃 → handleBrowserCrashed 自动重建（60s 内 3 次熔断）；桌面其他功能不受影响（CEF 多进程隔离）；
  6. 组件市场：索引拉取 / SHA-256 校验 / 解压注册 / 版本对比（第 5 节）。

10. 设计决策记录（明确不做）

不做项原因
linwidget SDK / TS 类型 / API 文档站点开发者是 AI，不需要人向的编程拐杖；规范 + 示例 + 校验器已覆盖
设计令牌 / 视觉规范强制用户决策：视觉自由，作者发挥
存储权限读写分离过度设计，协议复杂度上升而收益低
窗口遮挡检测挂起桌面层级复杂，实现成本高、收益低；挂起只由最小化/隐藏触发
settings.html 强制迁移到 schema破坏既有组件；两种方式并存，新组件推荐 schema
组件数据快照机制storage 已持久化，快照是重复设计
内嵌 AI 生成功能承诺主路径是外部 AI 工具生成 + 本地校验安装；内嵌生成仅远期探索
第三方组件索引供应链风险，只信任官方仓库
独立壁纸运行时（LinWallpaperWebViewRuntime 模式）壁纸是组件系统内的 role=wallpaper 特殊组件类型，不复刻独立子系统（见第 8 节）
拖放进组件（桌面→组件）同进程 OLE drag&drop 可用，但需 desktop 权限 + 命中协议；P3 探索，组件内拖拽不受影响
多进程方案（LinWidgetHost.exe）2026-10-13 已否决：收益（瘦身/进程隔离）对本场景有限，IPC/跨进程显示/事件回传复杂度高；组件"独立"由包级动态加载实现（见第 1 节决策记录）

11. 优先级路线与验收要点（单进程落地）

级别内容验收要点
P0CEF 四项缺口（第 3 节）+ 组件包加载器与注册表（第 9 节）+ 协议规范定稿（4.1）+ 校验器静态部分（4.3）组件包目录可被扫描、校验、注册并启动实例；组件内中文输入候选框正常；组件包内图片/字体/相对路径 JS 全部可加载；调试面板可见组件 console；无网络权限组件发起外联被拦

P1组件包市场（索引/安装/更新，第 5 节）+ 诊断包导出与意图保留（4.4/4.5）+ 权限申请流与订阅推送（6.2/6.3）在线装/卸/更新组件全流程可用；卸载后组件实例停止且用户数据保留；拒绝权限后组件 API 返回 DENIED 且不重复弹窗；一键导出的诊断包可直接喂 AI 完成一次增量修复

12. 风险与依赖

  • 校验器规则质量：与权限模型的联动判定（4.3）是防误伤关键，规则需随真实组件反馈迭代，起步宁严勿松（error 集小、warning 集大）；
  • scheme 是多项能力的共同前置：资源映射、CSP 注入都依赖 3.2，应优先于 P1 市场层完成；
  • GitHub 可达性：组件索引/更新依赖网络，离线降级（第 5 节）必须随市场层一同交付，避免更新失败打断组件使用；
  • 协议冻结：4.1 定稿后新增消息类型需评审，防止协议膨胀稀释 AI 生成正确率；
  • 命中测试细节：组件透明区域点击穿透到图标层需按帧 alpha 判断（isWidgetAt/widgetAt 扩展）；
  • 组件包目录一致性：用户手动删除/替换包目录时注册表可能残留——加载器启动时对账，失效条目自动清理或标记不可用；
  • 崩溃风暴：组件实例反复崩溃 → 60s 内 3 次熔断 + 用户提示；CEF crash-dumps-dir 日志辅助定位；
  • AI 生成质量下限：由校验器 + 沙箱兜底，不承诺"生成即正确"；坏组件在安装前被拦、运行中被治理。
组件系统方案（单进程 · 组件包动态加载）由多轮设计讨论收敛定稿；多进程方案已否决（决策记录见第 1 节），供 antigravity / 开发者排期执行。
