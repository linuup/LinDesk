LinDesk 组件系统方案（独立进程 · 与主程序设计）

读者：antigravity / 开发者 性质：组件平台打磨 + 主程序设计任务书 范围：组件系统（linwidget + CEF OSR + 壁纸）在独立进程架构下的完整设计 更新：2026-10-13

1. 背景与定位

LinDesk 的差异化价值在于 HTML 组件系统：任何 HTML/CSS/JS 内容都能成为桌面组件。组件系统已拍板独立为单独进程 LinWidgetHost.exe（见组件独立进程方案），主程序默认不携带 CEF 与组件代码、无组件可独立运行。

本方案在独立进程架构之上，把组件系统从"能用的容器"打磨成"可生长的平台"，并明确与主程序的设计边界——哪些能力在 Host、哪些在主程序、如何通过控制通道协同。

核心开发者是 AI 而不是人（已拍板）：SDK、TS 类型、API 文档站点等"人向"工具一律不做。平台的三项职责是——

  • 给 AI 清晰的规则：协议规范极简固定、示例组件可参考；
  • 给 AI 及时的反馈：校验器报错、运行时日志/异常可导出、意图可保留；
  • 给 AI 的产物安全兜底：权限最小化、危险代码拦截、资源限制。

视觉自由（已拍板）：不做设计令牌、不做视觉规范强制。组件长什么样由作者和用户决定，平台只管功能、安全与迭代闭环。

消息载荷 / 语义对应组件能力

协议边界：控制通道只承载低频控制消息——不传渲染帧、不逐事件转发输入（输入由组件窗口 HWND 直收）。组件内部的高频数据（system_info 推送、console 流）全部在 Host 进程内闭环，不过 IPC。

2.4 主程序侧集成设计

  • WidgetHostClient（主程序新组件）：QLocalSocket 客户端 + 进程拉起/监控/心跳 + 崩溃熔断 + 消息封装，替代原 89 处 WidgetManager 直接调用中的交互类调用；
  • manifest 探测：启动时检查 <userDataDir>/runtime/linwidget/manifest.json——不存在则不拉起 Host、不建管道、组件入口（右键菜单项、设置页组件区）隐藏；
  • 启动时序：主程序启动延迟 100ms → 探测 manifest → 拉起 LinWidgetHost.exe --parent <pid> → 握手（5s 超时）→ 下发桌面 HWND → 同步布局；CEF 由 Host 内部懒初始化（100ms 延迟策略保留），就绪后 status 上报；
  • 崩溃重启：监听 Host 进程退出 + 管道断开 → 区分正常/崩溃 → 自动重启；5 分钟最多 3 次，超限降级为"组件停用 + 提示"（避免崩溃风暴）；
  • 退出：aboutToQuit → shutdown → 等 Host 优雅退出（2s 超时强杀）；Host 侧父进程消失兜底退出；
  • 设置页"组件运行时"区：未安装=引导下载（Releases 直链）；已安装=版本 + 启用/停用开关 + 打开组件管理 + 检查更新 + 卸载；默认检测到 manifest 即启用。

3. 前置地基：CEF 四项技术缺口（P0，Host 内先行）

打磨建立在渲染栈完整之上。以下四项是当前 CEF 迁移遗留的功能缺口，必须先补齐（全部在 Host 进程内实现），否则作者层（运行时反馈）与运行层（权限沙箱）无从谈起。

4. 作者层：AI 开发闭环（Host 内）

AI 不需要 SDK，需要"规范 + 示例 + 校验器 + 反馈"。作者层的五个环节构成闭环：AI 读规范与示例 → 生成组件包 → 校验器报错 → AI 按错误修 → 安装运行 → 诊断导出再迭代。校验器与诊断包运行在 Host 进程（安装/调试入口均经 open_settings 通道）。

4.1 协议规范（定稿）

  • 以现有 handleRuntimeMessage（WidgetManager.cpp:1906）已支持的消息面为准，收敛固化，不新增无谓类型：geometry、settings、system_info、storage、实例管理（create/list/close）、error 等；
  • 字段命名统一 snake_case；每类消息配一个请求/响应 JSON 示例；
  • 错误码固定 3 个：OK / DENIED（权限拒绝）/ INVALID（参数或格式错误），拒绝与失败必须显式返回错误码而非静默；
  • 文档短到能整段放入 AI 上下文，作为组件生成的输入素材。

4.2 示例组件仓库

  • GitHub 开源：官方最小组件模板 + 3 个完整参考实现（Clock / Notes / Todo）；
  • 既是 AI 生成的 few-shot 素材，也是人工调试的对照物；
  • 仓库同时承载组件索引（见第 5 节）。

4.3 组件校验器

  • 安装时 lint：manifest 字段完整性、权限是否声明、HTML/JS 语法；
  • 输出结构化错误清单（位置 + 原因 + 修法），可直接反馈给 AI 迭代；
  • 危险模式扫描分级：error 确定有害（eval + 远程代码执行、远程脚本注入）；warning 可疑（内联事件、超大包、未声明权限却出现外部请求）；
  • 与权限模型联动（防误伤）：外部请求类代码只有在"manifest 未声明对应权限"时才判为错误——Weather 组件合法请求天气 API 不因出现外联 URL 被拦。

4.4 运行时反馈与诊断包

  • console / 未捕获异常 / 网络请求记录转发到 Host 调试面板日志查看器（依赖 3.3 缺口）；
  • 调试面板提供一键导出诊断包：组件 manifest + 运行日志 + 异常 + 最近错误，格式化为可直接粘贴给 AI 的文本；
  • 脱敏约束：诊断包只含组件自身数据，不包含用户桌面其他信息。

4.5 意图保留

  • manifest 记录生成意图（原始需求描述 + AI 引擎/版本）；
  • 组件出问题时，把"旧包 + 意图 + 新需求 + 诊断包"四件套喂给 AI，做增量修复而非推倒重写，成功率更高、结果更稳定。

4.6 生成入口（远期可选，不做承诺）

  • 主路径（现在就用）：用户在任意 AI 工具（Cursor / 豆包等）里按规范 + 模板生成组件包，LinDesk 负责校验与安装；
  • 远期可选：Host 调试面板内"描述式生成"（调大模型 API 返回组件包），仅作探索，不作为本方案交付项。

5. 市场层：组件发现与更新（Host 执行）

复用此前已完成设计的 GitHub 更新方案思路（客户端请求 GitHub Releases API + gh CLI 发布 + digest 免手算）同构实现，不引入新基建。下载/校验/安装/卸载由 Host 执行，主程序设置页只提供入口与安装状态。

能力设计要点
组件索引GitHub 仓库根目录 index.json：组件 id / 名称 / 简介 / 图标 / 最新版本 / 包下载 URL与组件示例仓库合并维护，版本号由发布流程统一管理（避免 AI 乱写版本）
在线安装 / 卸载拉取 index.json → 展示列表 → 下载 .lw 组件包 → SHA-256 校验 → 解压到组件目录 → 注册校验失败拒绝安装并提示原因；卸载保留用户数据（storage 按组件隔离，卸载仅移除代码）
组件更新启动时（或手动）对比已装版本与索引最新版，提示一键更新复用 UpdateChecker / compareVersions 数字语义；更新前备份旧包可回滚
离线降级GitHub 不可达时组件照常运行仅不提示更新；安装/更新按钮置灰并说明原因，不做静默失败
来源信任哈希校验 + 来源白名单（官方仓库固定）第三方索引暂不支持，避免供应链风险

6. 运行层：权限、推送、生命周期、沙箱（Host 内）

6.1 权限模型（收敛，避免过度设计）

  • 保持三类为主：network（外联请求）/ storage（组件数据读写）/ desktop（桌面集成：拖放、文件、快捷键预留）；可选扩展 clipboard；
  • 不做存储读写分离：拆"读/写"两个权限增加协议复杂度、收益低，组件作者与 AI 都更难理解；
  • 安装时最小化授予：只授予 manifest 声明且校验器通过的权限。

6.2 运行时申请流

  • 组件首次调用未授权权限时，Host 弹窗询问；请求挂起等待用户决策，避免组件无限重试；
  • 拒绝后该 API 返回 DENIED 错误码（协议可见，AI 能据此修）；
  • 同组件同权限记住选择，不重复弹窗；用户可在 Host 调试面板权限页随时撤销。

6.3 订阅-推送

  • system_info 在现有 request/response 基础上增加 subscribe / unsubscribe；
  • 推送按 1s 节流，组件挂起时不推送、恢复后补一帧；
  • 组件必须显式取消订阅，避免泄漏（组件销毁时平台强制清理）。

6.4 生命周期（定义要克制）

  • 挂起条件：窗口最小化 / 组件被显式隐藏时暂停渲染帧（OSR WasHidden）；不做窗口遮挡检测（桌面层级复杂、收益低）；
  • 内存压力时按 LRU 卸载挂起组件的 OSR 实例；恢复时重建实例 + 加载组件包 + 从 storage 恢复状态（成本明确：一次实例创建 + reload）；
  • 状态恢复依赖 layout.json（geometry，已有）与 storage（组件数据，已持久化）——不再设计额外的数据快照机制。

6.5 沙箱

  • 网络：OnBeforeResourceLoad 按 6.1 权限放行/拦截（补 3.4 缺口）；
  • CSP：随 linwidget:// scheme 响应统一注入，锁定远程脚本/外联字体等（随 3.2 缺口一并实现，不单独立项）；
  • 资源配额：组件存储上限（如 16MB），超限 API 返回 INVALID 并提示。

7. 体验层：设置、状态、交互（独立进程口径）

能力设计说明
设置 UImanifest 声明 settingsSchema（开关/滑块/下拉/颜色），Host 自动渲染设置对话框；与组件自带 settings.html 并存schema 是新组件推荐方式；既有组件（如 Notes 的 settings.html）保留，不做强制迁移，避免破坏性改动；设置入口在 Host 组件管理窗口
状态恢复重启恢复组件位置（registry.json）与数据（storage）Host 内完成；主程序只在下发 sync_layout 时告知桌面就绪
组件内交互拖拽吸附网格、Shift 锁定、右键层级菜单、多选批量移动——组件窗口在 Host 内自处理在现有 geometry 同步（WidgetGeometryChanged）基础上加交互层；不跨进程
跨进程拖放（拖文件进组件）边界项：需 OLE drag&drop 跨进程，成本高本次不做，列入 P3 探索；组件内拖拽不受影响
点击穿透 / 命中测试组件区域可交互、区域外穿透；主程序按 Host 上报几何表维护 widgetAt组件几何经 instance_event 增量同步，避免逐事件转发
视觉无强制约束作者与用户发挥；平台不注入设计令牌、不限制样式

8. 壁纸组件（role: wallpaper，Host 全屏窗口）

8.1 定位与设计原则

动态壁纸是组件系统内部的特殊组件类型（manifest.role: "wallpaper"），与普通组件共用包规范、CEF OSR 实例、消息桥、权限模型、注册表与调试面板入口。不做独立运行时，不复刻 WebView2 时代的 LinWallpaperWebViewRuntime。组件系统只有一种组件，role 只区分行为。独立进程架构下，壁纸 = Host 进程的全屏透明窗口（SetParent 到桌面窗口，Z 序最低）。

8.2 现状盘点（代码依据）

层现状结论

持久化filterWallpapers 按 role 过滤（WidgetManager.cpp:956），壁纸不落 layout.json，走独立壁纸配置（LinWallpapers/Enabled）隔离持久化已设计

10. 设计决策记录（明确不做）

不做项原因
linwidget SDK / TS 类型 / API 文档站点开发者是 AI，不需要人向的编程拐杖；规范 + 示例 + 校验器已覆盖
设计令牌 / 视觉规范强制用户决策：视觉自由，作者发挥
存储权限读写分离过度设计，协议复杂度上升而收益低
窗口遮挡检测挂起桌面层级复杂，实现成本高、收益低；挂起只由最小化/隐藏触发
settings.html 强制迁移到 schema破坏既有组件；两种方式并存，新组件推荐 schema
组件数据快照机制storage 已持久化，快照是重复设计
内嵌 AI 生成功能承诺主路径是外部 AI 工具生成 + 本地校验安装；内嵌生成仅远期探索
第三方组件索引供应链风险，只信任官方仓库
独立壁纸运行时（LinWallpaperWebViewRuntime 模式）壁纸是组件系统内的 role=wallpaper 特殊组件类型，不复刻独立子系统（见第 8 节）
跨进程拖放（拖文件进组件）OLE drag&drop 跨进程成本高，收益低；组件内拖拽不受影响（P3 探索）
组件 console / 高频数据过 IPC全部在 Host 进程内闭环；控制通道只传低频控制消息，避免协议膨胀

12. 风险与依赖

  • 校验器规则质量：与权限模型的联动判定（4.3）是防误伤关键，规则需随真实组件反馈迭代，起步宁严勿松（error 集小、warning 集大）；
  • scheme 是多项能力的共同前置：资源映射、CSP 注入都依赖 3.2，应优先于 P1 市场层完成；
  • GitHub 可达性：组件索引/更新依赖网络，离线降级（第 5 节）必须随市场层一同交付，避免更新失败打断组件使用；
  • 协议冻结：4.1 定稿后新增消息类型需评审，防止协议膨胀稀释 AI 生成正确率；
  • 窗口化穿透细节：组件窗口透明区域点击穿透到图标层需命中测试协作（HTTRANSPARENT + 几何表）；
  • 双进程数据一致性：主程序退出时 Host 正在写 registry.json——退出时序先 shutdown 等收尾（2s 超时强杀），文件写入用现有原子写；
  • 崩溃风暴：Host 反复崩溃 → 5 分钟 3 次熔断 + 用户提示；CEF crash-dumps-dir 日志辅助定位；
  • AI 生成质量下限：由校验器 + 沙箱兜底，不承诺"生成即正确"；坏组件在安装前被拦、运行中被治理。
