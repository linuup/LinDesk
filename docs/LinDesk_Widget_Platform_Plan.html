LinDesk 组件系统方案（单进程 · 运行时动态加载）

读者：antigravity / 开发者 性质：组件平台打磨 + 与主程序集成任务书 范围：组件系统运行时经 LinDesk 安装/卸载（动态加载）；组件包独立分发；CEF 缺口；AI 开发闭环；按代码细分的任务清单 更新：2026-10-14

1. 背景与定位

LinDesk 的差异化价值在于 HTML 组件系统：任何 HTML/CSS/JS 内容都能成为桌面组件。组件系统运行在主程序进程内（单进程），但组件系统本体（运行时）与业务组件都不捆绑进主程序：用户经 LinDesk 安装/卸载组件系统运行时，再动态下载/放置组件包即加载。

决策记录（2026-10-13）：

  • 决策 1 · 放弃多进程：此前设计的 LinWidgetHost.exe 独立进程方案已否决（备份于 _backup/LinDesk_Widget_Host_Plan-v1.html）：CEF 本身是多进程架构（渲染进程崩溃不会拖垮主程序，已有 handleBrowserCrashed 自动重建），额外进程隔离收益边际小；而跨进程显示/传帧/事件回传引入的复杂度远大于收益。组件系统的"独立"不由进程隔离实现。
  • 决策 2 · 组件系统本身可安装/卸载（动态加载）：先实现动态加载——通过 LinDesk 安装组件系统运行时、卸载组件系统运行时（是运行时的安装/卸载，不是组件的启用/关闭）。当前组件系统随主程序捆绑编译（CMakeLists glob 收源），无"安装/卸载"概念，此能力目前未实现，列为 P0 首要任务（见第 2 节）。

本方案把组件系统从"能用的容器"打磨成"可生长的平台"，并明确与主程序的集成边界——组件系统如何安装/卸载（动态加载）、组件包如何动态加载、运行时如何渲染合成、交互如何路由、数据如何归属。

核心开发者是 AI 而不是人（已拍板）：SDK、TS 类型、API 文档站点等"人向"工具一律不做。平台的三项职责是——

  • 给 AI 清晰的规则：协议规范极简固定、示例组件可参考；
  • 给 AI 及时的反馈：校验器报错、运行时日志/异常可导出、意图可保留；
  • 给 AI 的产物安全兜底：权限最小化、危险代码拦截、资源限制。

视觉自由（已拍板）：不做设计令牌、不做视觉规范强制。组件长什么样由作者和用户决定，平台只管功能、安全与迭代闭环。

2. 组件系统的安装与卸载（动态加载，P0 首要）

2.1 现状与目标

2.3 安装流程（用户经 LinDesk 执行，全程不重启主程序）

  1. 入口：设置页"组件系统"区显示"未安装"→ 点击 [下载并安装组件系统]；
  2. 获取：主程序请求 GitHub Releases 最新 linwidget-runtime 包 → 下载 zip → SHA-256 校验（失败拒绝安装并提示原因）；
  3. 落地：解压到临时目录 → 校验 manifest.json 字段完整 → 原子 move 到 <userData>/runtime/linwidget/（防止半包残留）；
  4. 加载：LoadLibrary(LinWidgetRuntime.dll) → linwidget_init(desktopCtx) → CEF 懒初始化（100ms 延迟策略保留）→ WidgetManager 装配；
  5. 生效：组件入口出现（右键菜单组件项、设置页组件区、调试面板组件页）；运行时版本写入 config.ini 组件段；
  6. 失败处理：DLL 加载失败 / CEF 初始化失败 → 明确提示原因（版本不匹配、杀软拦截、缺 VC 运行库），不做静默失败；已解压目录标记不可用，可重试。

2.4 卸载流程（用户经 LinDesk 执行）

  1. 设置页"组件系统"区 [卸载组件系统] → 确认提示（组件数据与组件包保留，重新安装后自动恢复）；
  2. 停干净：停止全部组件实例 + 壁纸 → linwidget_shutdown()（释放 CEF、退出消息桥、收尾 registry 原子写）→ FreeLibrary；
  3. 清目录：删除 <userData>/runtime/linwidget/；保留 <userData>/LinWidgets/（组件包）、LinWidgetsData/（组件数据）、LinWallpapers/（壁纸配置）；
  4. 回到未安装态：组件入口全部隐藏，仅保留"安装组件系统"入口；主程序全程保持运行，桌面其余功能不受影响。

2.5 更新流程

  1. 设置页 [检查更新] → 对比 manifest.json 的 runtimeVersion 与 Releases 最新版（复用 UpdateChecker / compareVersions 数字语义）；
  2. 下载新版 → SHA-256 校验 → 旧包目录改名保留为备份（如 runtime/linwidget.old/）；
  3. 停组件 → linwidget_shutdown → FreeLibrary → 替换为新版目录 → 重新 LoadLibrary + linwidget_init；
  4. 按 registry 恢复组件实例；加载失败自动回滚到 .old 备份并提示。

2.6 主程序动态加载设计（DLL 方案）

  • 导出接口（新文件 src/desktop/widgets/runtime_export.h，纯 C 接口避免 ABI 耦合；不跨 DLL 边界传 std::string / Qt 对象，指针 + 长度或封装结构体）： 
    extern "C" {
  bool linwidget_is_loaded();                         // 运行时是否已加载
  bool linwidget_load();                              // LoadLibrary + 符号解析
  bool linwidget_unload();                            // FreeLibrary
  bool linwidget_init(const LinWidgetDesktopCtx* ctx); // CEF 初始化 + WidgetManager 装配
  void linwidget_shutdown();                          // 停组件 + CEF 收尾
  void* linwidget_widget_manager();                   // 返回 WidgetManager*（主程序连信号/调用）
  void linwidget_render_canvas(...);                  // 渲染合成钩子（ListView 调用）
  bool linwidget_forward_event(...);                  // 输入转发钩子（ListView 调用）
}
  • 未安装态门控：主程序持有运行时模块句柄（nullptr = 未安装）；ListView.cpp 的 canvas 合成调用（:1344-1345 / :1381-1382）与输入转发点（forwardMouseEvent / forwardWheelEvent / forwardKeyEvent / forwardInputMethodEvent 等 10+ 处）改为函数指针判空调用——未安装时桌面渲染与交互零组件开销；
  • 事件信号：主程序经 linwidget_widget_manager() 拿到的指针连接现有信号（widgetError / widgetLaunched / widgetStopped / widgetSettingsRequested / widgetGeometryChanged），与当前单进程行为一致；
  • CEF 子进程：运行时包内 subprocess.exe 作为 CEF 子进程入口（原 subprocess/main.cpp 产物迁入运行时包）；CEF 在 DLL 内初始化、在主程序进程内运行。

2.7 未安装态与引导

  • 设置页"组件系统"区：显示未安装 + 版本说明 + [下载并安装组件系统]；
  • 右键菜单：无组件相关项；调试面板组件页：提示"组件系统未安装"并给安装入口；
  • 验证口径：主程序安装包不含组件系统，未安装时主程序无组件代码可独立编译运行（组件源已从主程序目标拆出）。

2.8 代码改造点（摘要；明细见第 10 节任务清单）

  1. CMakeLists.txt（根）：新增 add_library(LinWidgetRuntime SHARED ...) 目标，收 widgets/linwidget/ + widgets/cef/ + widgetmanager 源；主程序目标移除组件源与 CEF 链接；CEF 头文件/库只在 runtime 目标使用；
  2. src/desktop/widgets/runtime_export.h/.cpp：新增，C 导出接口 + LoadLibrary/FreeLibrary 管理；
  3. main.cpp（:140 CefManager::shutdown()）：组件初始化/收尾改为运行时门控（已加载才 init/shutdown）；
  4. ListView.cpp（:1344-1345 / :1381-1382 合成；10+ 输入转发点）：改经 runtime 接口判空调用；
  5. src/desktop/runtime/RuntimeInstaller.h/.cpp：新增，安装/卸载/更新全流程（下载、SHA-256、解压、LoadLibrary、卸载清目录）；
  6. 设置页组件系统区 UI（未安装/已安装/更新/卸载状态与按钮）；
  7. scripts/package_linwidget_runtime.ps1：新增，打包运行时 zip 并发布 Releases。

2.9 数据隔离保证（不触碰老版本图标 / box 数据）

检索现有实现（AppPaths / BoxManager / LayoutPersistenceService / ConfigManager）后确认数据归属如下：

三条硬约束（写进验收）：

  1. 组件系统运行时安装 / 卸载 / 更新只操作 <userData>/runtime/linwidget/ 与 config.ini 的组件系统段；
  2. 图标/box 数据文件（data.dat / data.json）及其 .tmp / .bak 伴生文件绝不被组件系统任何流程读写——含安装、卸载、更新、组件运行期；
  3. 拆 DLL 时桌面数据逻辑留在主程序：BoxManager / LayoutPersistenceService / DesktopItemLoader（图标加载与布局持久化）不迁入 LinWidgetRuntime.dll；拆 DLL 只影响渲染合成（ListView.cpp:1344-1345/:1381-1382）与输入转发（10+ 处）两个挂点，且以接口判空跳过实现——未安装组件系统时桌面图标/box 的加载、绘制、持久化行为与老版本完全一致。

3.3 组件与主程序的接口面（同进程）

  • 运行时消息协议：handleRuntimeMessage（WidgetManager.cpp:1906）收敛固化：geometry、settings、system_info、storage、实例管理（create/list/close）、error——同进程信号/回调直连，无 IPC 封装；
  • 事件信号：保留现有 widgetError / widgetLaunched / widgetStopped / widgetSettingsRequested / widgetGeometryChanged 信号，主程序 UI（设置页、右键菜单、命中测试）经 linwidget_widget_manager() 指针直接连接；
  • 输入注入：ListView 事件 → linwidget_forward_event → WidgetManager forward*Event → CefOsrBrowserInstance（现有链路，无跨进程跳转，延迟最低）；
  • 高频数据：system_info 订阅推送、console 流全部在主程序进程内闭环，直接进调试面板日志查看器。

3.4 组件包动态加载集成设计

  • 组件目录扫描：运行时初始化时扫描 <userData>/LinWidgets/ 下每个组件包目录 → 读取 manifest.json → 校验器 lint → 注册进 registry.json；目录不存在则为空态（无组件不报错）；
  • 动态加载/卸载：新增包目录 → 即时校验注册并可启动实例；删除包目录/卸载 → 停止实例、仅移除代码，storage 数据保留；无需重启主程序（加载器监听目录变化或手动刷新）；
  • 入口显隐：右键菜单组件项、设置页组件区按"运行时已装 + 是否已装组件"动态显示；零组件安装时入口正常存在并引导去下载；
  • 崩溃恢复：单个组件 OSR 实例崩溃 → handleBrowserCrashed 自动重建（60s 内 3 次熔断）；桌面其他功能不受影响（CEF 多进程隔离）；
  • 版本兼容：组件包 manifest 声明 runtimeVersion / protocolVersion；不兼容 → 加载器拒绝并提示更新组件包或组件运行时；
  • 设置页组件区：组件列表（名称/版本/启用状态）+ [下载组件]（Releases 直链）+ [检查更新] + [卸载] + [打开组件管理]。

5. 作者层：AI 开发闭环（组件运行时内）

AI 不需要 SDK，需要"规范 + 示例 + 校验器 + 反馈"。作者层的五个环节构成闭环：AI 读规范与示例 → 生成组件包 → 校验器报错 → AI 按错误修 → 安装运行 → 诊断导出再迭代。校验器与诊断包运行在组件运行时（安装/调试入口在组件管理窗口与调试面板）。

5.1 协议规范（定稿）

  • 以现有 handleRuntimeMessage（WidgetManager.cpp:1906）已支持的消息面为准，收敛固化，不新增无谓类型：geometry、settings、system_info、storage、实例管理（create/list/close）、error 等；
  • 字段命名统一 snake_case；每类消息配一个请求/响应 JSON 示例；
  • 错误码固定 3 个：OK / DENIED（权限拒绝）/ INVALID（参数或格式错误），拒绝与失败必须显式返回错误码而非静默；
  • 文档短到能整段放入 AI 上下文，作为组件生成的输入素材。

5.2 示例组件仓库

  • GitHub 开源：官方最小组件模板 + 3 个完整参考实现（Clock / Notes / Todo）；
  • 既是 AI 生成的 few-shot 素材，也是人工调试的对照物；
  • 仓库同时承载组件索引（见第 6 节）。

5.3 组件校验器

  • 安装时 lint：manifest 字段完整性、权限是否声明、HTML/JS 语法；
  • 输出结构化错误清单（位置 + 原因 + 修法），可直接反馈给 AI 迭代；
  • 危险模式扫描分级：error 确定有害（eval + 远程代码执行、远程脚本注入）；warning 可疑（内联事件、超大包、未声明权限却出现外部请求）；
  • 与权限模型联动（防误伤）：外部请求类代码只有在"manifest 未声明对应权限"时才判为错误——Weather 组件合法请求天气 API 不因出现外联 URL 被拦。

5.4 运行时反馈与诊断包

  • console / 未捕获异常 / 网络请求记录转发到调试面板日志查看器（依赖 4.3 缺口）；
  • 调试面板提供一键导出诊断包：组件 manifest + 运行日志 + 异常 + 最近错误，格式化为可直接粘贴给 AI 的文本；
  • 脱敏约束：诊断包只含组件自身数据，不包含用户桌面其他信息。

5.5 意图保留

  • manifest 记录生成意图（原始需求描述 + AI 引擎/版本）；
  • 组件出问题时，把"旧包 + 意图 + 新需求 + 诊断包"四件套喂给 AI，做增量修复而非推倒重写，成功率更高、结果更稳定。

5.6 生成入口（远期可选，不做承诺）

  • 主路径（现在就用）：用户在任意 AI 工具（Cursor / 豆包等）里按规范 + 模板生成组件包，LinDesk 负责校验与安装；
  • 远期可选：调试面板内"描述式生成"（调大模型 API 返回组件包），仅作探索，不作为本方案交付项。

6. 市场层：组件包发现与更新（组件运行时执行）

复用此前已完成设计的 GitHub 更新方案思路（客户端请求 GitHub Releases API + gh CLI 发布 + digest 免手算）同构实现，不引入新基建。下载/校验/安装/卸载由组件运行时执行，设置页组件区提供入口与安装状态。

能力设计要点
组件索引GitHub 仓库根目录 index.json：组件 id / 名称 / 简介 / 图标 / 最新版本 / 包下载 URL与组件示例仓库合并维护，版本号由发布流程统一管理（避免 AI 乱写版本）

来源信任哈希校验 + 来源白名单（官方仓库固定）第三方索引暂不支持，避免供应链风险

7. 运行层：权限、推送、生命周期、沙箱（组件运行时内）

7.1 权限模型（收敛，避免过度设计）

  • 保持三类为主：network（外联请求）/ storage（组件数据读写）/ desktop（桌面集成：拖放、文件、快捷键预留）；可选扩展 clipboard；
  • 不做存储读写分离：拆"读/写"两个权限增加协议复杂度、收益低，组件作者与 AI 都更难理解；
  • 安装时最小化授予：只授予 manifest 声明且校验器通过的权限。

7.2 运行时申请流

  • 组件首次调用未授权权限时，主程序弹窗询问；请求挂起等待用户决策，避免组件无限重试；
  • 拒绝后该 API 返回 DENIED 错误码（协议可见，AI 能据此修）；
  • 同组件同权限记住选择，不重复弹窗；用户可在调试面板权限页随时撤销。

7.3 订阅-推送

  • system_info 在现有 request/response 基础上增加 subscribe / unsubscribe；
  • 推送按 1s 节流，组件挂起时不推送、恢复后补一帧；
  • 组件必须显式取消订阅，避免泄漏（组件销毁时平台强制清理）。

7.4 生命周期（定义要克制）

  • 挂起条件：窗口最小化 / 组件被显式隐藏时暂停渲染帧（OSR WasHidden）；不做窗口遮挡检测（桌面层级复杂、收益低）；
  • 内存压力时按 LRU 卸载挂起组件的 OSR 实例；恢复时重建实例 + 加载组件包 + 从 storage 恢复状态（成本明确：一次实例创建 + reload）；
  • 状态恢复依赖 layout.json（geometry，已有）与 storage（组件数据，已持久化）——不再设计额外的数据快照机制。

7.5 沙箱

  • 网络：OnBeforeResourceLoad 按 7.1 权限放行/拦截（补 4.4 缺口）；
  • CSP：随 linwidget:// scheme 响应统一注入，锁定远程脚本/外联字体等（随 4.2 缺口一并实现，不单独立项）；
  • 资源配额：组件存储上限（如 16MB），超限 API 返回 INVALID 并提示。

11. 设计决策记录（明确不做）

不做项原因
linwidget SDK / TS 类型 / API 文档站点开发者是 AI，不需要人向的编程拐杖；规范 + 示例 + 校验器已覆盖
设计令牌 / 视觉规范强制用户决策：视觉自由，作者发挥
存储权限读写分离过度设计，协议复杂度上升而收益低
窗口遮挡检测挂起桌面层级复杂，实现成本高、收益低；挂起只由最小化/隐藏触发
settings.html 强制迁移到 schema破坏既有组件；两种方式并存，新组件推荐 schema
组件数据快照机制storage 已持久化，快照是重复设计
内嵌 AI 生成功能承诺主路径是外部 AI 工具生成 + 本地校验安装；内嵌生成仅远期探索
第三方组件索引供应链风险，只信任官方仓库
独立壁纸运行时（LinWallpaperWebViewRuntime 模式）壁纸是组件系统内的 role=wallpaper 特殊组件类型，不复刻独立子系统（见第 9 节）
拖放进组件（桌面→组件）同进程 OLE drag&drop 可用，但需 desktop 权限 + 命中协议；P3 探索，组件内拖拽不受影响
多进程方案（LinWidgetHost.exe）2026-10-13 已否决：收益（瘦身/进程隔离）对本场景有限，IPC/跨进程显示/事件回传复杂度高；组件"独立"由运行时动态加载 + 组件包动态加载实现（见第 1 节决策记录）
组件运行时二次启停开关安装/卸载（第 2 节）已覆盖"要不要组件系统"；运行期再给启停开关是重复设计，入口显隐随安装状态即可

13. 风险与依赖

  • DLL 加载 / CEF 初始化失败：版本不匹配、杀软拦截、缺 VC 运行库都可能使安装后加载失败——安装流程必须显式报错（原因 + 建议），不做静默失败；失败目录标记不可用可重试；
  • 运行时更新中断：下载半包 / 替换中断——解压先落临时目录 + 原子 move，旧包 .old 备份保留，加载失败自动回滚；
  • 卸载数据语义：卸载组件系统不删组件包/组件数据/壁纸配置（LinWidgets/、LinWidgetsData/、LinWallpapers/），重新安装后自动恢复；确认弹窗需写明该语义，避免用户误以为数据丢失；
  • 数据隔离红线：组件系统安装/卸载/更新流程禁止读写 %APPDATA%/LinDesk/data.dat|data.json（桌面图标/box 布局）及 .tmp/.bak 伴生文件；拆 DLL 时 BoxManager / LayoutPersistenceService / DesktopItemLoader 必须留在主程序侧（2.9 三条硬约束列入验收）；
  • 校验器规则质量：与权限模型的联动判定（5.3）是防误伤关键，规则需随真实组件反馈迭代，起步宁严勿松（error 集小、warning 集大）；
  • scheme 是多项能力的共同前置：资源映射、CSP 注入都依赖 4.2，应优先于 P1 市场层完成；
  • GitHub 可达性：运行时安装与组件索引/更新依赖网络，离线降级（第 6 节）必须随市场层一同交付；运行时已安装后离线不影响组件使用；
  • 协议冻结：5.1 定稿后新增消息类型需评审，防止协议膨胀稀释 AI 生成正确率；
  • 命中测试细节：组件透明区域点击穿透到图标层需按帧 alpha 判断（isWidgetAt/widgetAt 扩展）；
  • 组件包目录一致性：用户手动删除/替换包目录时注册表可能残留——加载器启动时对账，失效条目自动清理或标记不可用；
  • 崩溃风暴：组件实例反复崩溃 → 60s 内 3 次熔断 + 用户提示；CEF crash-dumps-dir 日志辅助定位；
  • AI 生成质量下限：由校验器 + 沙箱兜底，不承诺"生成即正确"；坏组件在安装前被拦、运行中被治理。
组件系统方案（单进程 · 运行时动态加载）由多轮设计讨论收敛定稿：P0 首要为组件系统经 LinDesk 安装/卸载（动态加载），其后按代码细化任务逐项落地；多进程方案已否决（决策记录见第 1 节），供 antigravity / 开发者排期执行。
