1. 背景与定位

LinDesk 的差异化价值在于 HTML 组件系统：任何 HTML/CSS/JS 内容都能成为桌面组件。组件系统运行在主程序进程内（单进程），但组件系统本体（运行时）与业务组件都不捆绑进主程序：用户经 LinDesk 安装/卸载组件系统运行时，再动态下载/放置组件包即加载。已实现

核心开发者是 AI 而不是人（已拍板）：SDK、TS 类型、API 文档站点等"人向"工具一律不做。平台三项职责——给 AI 清晰的规则（协议规范极简固定、示例组件可参考）、及时的反馈（校验器报错、日志/异常可导出）、产物安全兜底（权限最小化、危险代码拦截、资源限制）。

视觉自由（已拍板）：不做设计令牌、不做视觉规范强制。组件长什么样由作者和用户决定，平台只管功能、安全与迭代闭环。

2. 现状与已落地地基

2.1 运行时安装 / 卸载 已落地

组件系统已拆为 LinWidgetRuntime.dll（独立 SHARED 目标，含 WidgetManager / CEF OSR / 组件包加载器），经 RuntimeInstaller 安装到 <userData>/runtime/linwidget/ 并 LoadLibrary 动态加载；主程序经 C 导出接口判空调用，未安装时无组件代码、可独立编译运行。设置页可安装/卸载/更新运行时，全程不重启主程序；scripts/package_linwidget_runtime.ps1 打独立包（zip + sha256 + manifest）发 GitHub Releases。

数据隔离三条硬约束（验收红线）：

  1. 安装/卸载/更新只操作 <userData>/runtime/linwidget/ 与 config.ini 组件系统段；
  2. 图标/box 数据（data.dat|data.json 及 .tmp/.bak）绝不被组件系统任何流程读写；
  3. BoxManager / LayoutPersistenceService / DesktopItemLoader 留在主程序，不迁入运行时 DLL。

2.2 主程序集成（现状）

同进程单实例架构：主程序 LoadLibrary 加载 LinWidgetRuntime.dll；OSR 帧经 LinWidgetCanvasWidget 合成进桌面画布；ListView 捕获鼠标/滚轮/键盘/IME 经桥接口转发；isWidgetAt / widgetAt 按实例几何命中、透明区域穿透；组件包目录扫描 + manifest 校验 + registry 注册 + 实例创建/销毁；崩溃由 handleBrowserCrashed 自动重建（60s 内 3 次熔断）。

2.3 前置地基：CEF 四项缺口 已基本补齐

  • 本地资源 scheme：linwidget:// + GetResourceHandler，组件内图片/字体/相对路径 JS 全可加载。已实现
  • console 捕获：OnConsoleMessage → 调试面板日志查看器。已实现
  • 网络权限沙箱：OnBeforeResourceLoad 按 allowNetwork() 拦截 http/https/ws/wss/ftp。已实现
  • IME：组合/提交/取消已实现；待补 候选框查询回调（OnIMECandidateCountToQuery，P1 可选，参考 cefclient osr_ime_handler_win.cpp）。

P0 待办：组件包目录监听热加载（新增包目录即时注册、删除即时清理）+ 启动对账（用户手动删包后注册表失效条目自动清理/标记不可用）。任务见 8.1。

3. 作者层：AI 开发闭环（待办）

AI 不需要 SDK，需要"规范 + 示例 + 校验器 + 反馈"：AI 读规范与示例 → 生成组件包 → 校验器报错 → AI 按错误修 → 安装运行 → 诊断导出再迭代。

  • 3.1 协议规范：已定稿（docs/LinWidget_Protocol.md）——消息面收敛（geometry/settings/system_info/storage/实例管理/error）、snake_case、错误码 OK / DENIED / INVALID、每类消息带请求/响应示例、可整段放入 AI 上下文。
  • 3.2 示例组件仓库：P1 GitHub 开源官方模板 + 3 个完整参考实现（Clock / Notes / Todo），兼作 AI few-shot 素材与组件索引载体。
  • 3.3 组件校验器：P1（静态部分此前已定）安装 lint（manifest 字段/权限声明/语法）+ 危险模式分级（error：eval+远程执行、远程脚本注入；warning：内联事件/超大包/未声明权限却外联）+ 与权限模型联动防误伤（已声明权限的合法外联不误报）→ 输出结构化错误清单可直接回喂 AI。
  • 3.4 诊断包：P1 调试面板一键导出 manifest + 日志 + 异常 + 最近错误（只含组件自身数据），可直接粘贴给 AI 迭代。
  • 3.5 意图保留：P1 manifest 记录生成意图（需求描述 + AI 引擎/版本）；出问题时"旧包 + 意图 + 新需求 + 诊断包"四件套做增量修复。
  • 3.6 生成入口：主路径 = 用户在任意 AI 工具生成 → LinDesk 校验安装（现在就用）；调试面板内"描述式生成"仅远期探索，不做承诺。

5. 运行层：权限、推送、生命周期、沙箱（待办）

  • 5.1 权限模型：三类为主——network / storage / desktop（拖放/文件/快捷键预留），可选 clipboard；不做存储读写分离（过度设计）；安装时最小化授予。
  • 5.2 运行时申请流：P1 首次调用未授权权限 → 主程序弹窗询问、请求挂起等待决策；拒绝后 API 返回 DENIED；同组件同权限记住选择，可随时撤销。
  • 5.3 订阅-推送：P1 system_info 增加 subscribe/unsubscribe；1s 节流；组件挂起不推送、恢复补一帧；销毁强制清理订阅。
  • 5.4 生命周期：P2 挂起条件 = 窗口最小化/显式隐藏（不做遮挡检测）；内存压力按 LRU 卸载挂起 OSR 实例，恢复时重建 + 从 storage 恢复。
  • 5.5 沙箱：网络拦截已实现；P2 CSP 随 scheme 响应注入 + 组件存储配额（16MB，超限返回 INVALID）。

6. 体验层：设置、状态、交互 已落地

6.1 组件 Ctrl+拖拽移动 已落地

按住 Ctrl + 拖动组件即可实时移动组件位置，抬起鼠标持久化保存到 registry.json 与配置。ListView 鼠标事件通过修饰键精准区分交互模式：Ctrl = 组件移动修饰键。

场景行为实现要点
命中组件 + Ctrl + 拖动进入组件移动模式：主程序接管鼠标、设置 Qt::SizeAllCursor、不转发 OSR，按偏移实时更新组件 geometryListView press/move/release 三分支；bridge.widgetGeometry + setWidgetGeometry；Canvas 帧重定位无闪烁重绘
命中组件 + 无 Ctrl事件转发 OSR（组件内交互，保持不变）现有 forwardMouseEvent 链路
Ctrl + 点击（位移未超阈值）不进入移动，补发按压与释放到 OSR（保留组件内 Ctrl 快捷键）以 QApplication::startDragDistance() 阈值判定
未命中组件桌面图标选择/框选/拖拽（保持不变）现有 ListView 逻辑

边界保障：跨出桌面视口自动夹紧；壁纸组件（role: wallpaper）与默认页（__default_page__）受拦截保护不可拖动；拖拽抬起时立即触发 saveToConfig 持久化落盘。

7. 壁纸组件（role: wallpaper）与壁纸工坊 (Wallpaper Studio)

7.1 架构层级与生命周期 已落地

动态壁纸 = 组件系统内的特殊组件类型（manifest.role: "wallpaper"），与普通组件共用包规范、OSR 实例、消息桥、权限模型与 Canvas 合成；不做独立运行时。壁纸 = 全屏 OSR 实例，帧合成层级最低（普通组件之下、系统壁纸之上）；单例（同时仅一个活动壁纸）、不可拖拽、点击穿透。

P0 已落地：role 分流 + startWallpaper 全屏渲染、桌面视口绑定、层级与穿透、单例持久化（启动恢复/切换停旧）、内置壁纸包（图片/视频/轮播/本地文件选择骨架）。

7.2 壁纸工坊 (Wallpaper Studio)：可视化配置编辑器 P1

虽然组件系统底层面向 AI 生成（复杂动态算法、Canvas 粒子、天气联动），但对于终端用户，90% 的高频日常需求是自由设置本地收藏的静态壁纸或 MP4/WebM 视频。为避免简陋的“文件浏览”按钮引发比例变形、大黑边、音量爆音与桌面图标看不清等问题，规划专用的可视化配置编辑器——“壁纸工坊 (Wallpaper Studio)”：

  • 双轮驱动分工：AI 产出高级动效骨架与着色器模板；工坊编辑器负责普通用户媒体资产拖拽、所见即所得裁切、滤镜与参数装配；
  • 16:9 实时画板预览：等比还原屏幕，配备【桌面图标模拟剪影】浮层，所见即所得肉眼验证壁纸与图标的对比度；
  • 排版适配四模式：填充裁剪 (Cover)、等比完整 (Contain)、拉伸 (Stretch)、平铺 (Tile)；
  • 易读性滤镜：提供遮罩暗化 (0%~80%) 与背景高斯模糊 (0~20px) 滑块，保护桌面文件文字清晰辨识；
  • 视频音频控制：静音切换、音量无级调节 (0~100%)、播放速率 (0.5x~2.0x)；
  • 导出与生效：一键应用至当前桌面；一键导出标准 .lw 壁纸包。

7.3 视频性能治理 P1

视频壁纸按 30fps/60fps 帧率节流，与 5.4 生命周期策略一致：窗口最小化、全屏 3D 游戏或休眠时挂起暂停渲染，确保 CPU/GPU 0.0% 零抢占。

10. 风险与依赖

  • 数据隔离红线：组件系统任何流程禁止读写 data.dat|data.json 及伴生文件；拆 DLL 时 BoxManager / LayoutPersistenceService / DesktopItemLoader 留在主程序（见 2.1，列入验收）。
  • DLL 加载 / CEF 初始化失败：版本不匹配、杀软拦截、缺 VC 运行库——安装流程显式报错（原因 + 建议），不做静默失败。
  • 运行时更新中断：解压先落临时目录 + 原子 move，旧包 .old 备份，加载失败自动回滚。
  • 卸载数据语义：卸载组件系统不删组件包/组件数据/壁纸配置，重新安装自动恢复；确认弹窗写明该语义。
  • 校验器规则质量：与权限模型的联动判定是防误伤关键，随真实组件反馈迭代，起步宁严勿松（error 集小、warning 集大）。
  • GitHub 可达性：运行时安装与组件索引/更新依赖网络；离线降级随市场层一同交付；运行时已装后离线不影响组件使用。
  • 协议冻结：协议定稿后新增消息类型需评审，防止膨胀稀释 AI 生成正确率。
  • 组件包目录一致性：用户手动删/换包目录可能致注册表残留——启动对账自动清理（P0 待办）。
  • 崩溃风暴：组件实例反复崩溃 → 60s 内 3 次熔断 + 用户提示；crash-dumps-dir 日志辅助定位。
  • AI 生成质量下限：由校验器 + 沙箱兜底，不承诺"生成即正确"；坏组件安装前被拦、运行中被治理。
组件系统方案：P0 地基（运行时拆分/安装卸载、CEF 缺口、壁纸 P0）与第 6 章体验层（组件 Ctrl+拖拽移动、双栏组件管理窗口、settingsSchema 自动渲染与设置页联动）已全部落地验收。剩余待办集中在组件市场与作者层（P1）、生命周期治理（P2）。完成一项更新一项。
