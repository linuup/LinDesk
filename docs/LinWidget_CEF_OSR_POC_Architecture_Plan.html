Chromium Embedded Framework Off-Screen Rendering (OSR) Proof of Concept (POC)

CEF 离屏渲染最小可行性原型 (POC) 架构改造方案

本文档详细定义了在 LinDesk 项目中引入 Chromium Embedded Framework (CEF) 实现纯离屏像素渲染 (OSR) 的最小原型验证方案。通过在调试控制台内建立隔离测试沙箱，全方位验证 32 位 ARGB 透明通道、60fps 实时渲染以及鼠标事件注入。

1. 方案背景与目标边界

1.1 为何需要离屏渲染 (OSR)

在 Windows 桌面系统上，原生的 WebView 宿主通常拥有独立的操作系统窗口句柄（HWND）。当需要将 Web 画面置于桌面图标（ListView）下方时，传统的同级窗口（Sibling HWNDs）模式会遭遇 Win32 User32 的剪裁限制（Airspace Issue），无法实现两个重叠窗口之间的 Alpha 透明混合。

离屏渲染 (Off-Screen Rendering, OSR) 模式通过让 Chromium 引擎在内存后台渲染，不创建任何原生子窗口，每当页面局部或全局像素刷新时，直接将一帧 32 位的 BGRA 像素缓冲或 GPU 共享纹理通过回调吐给宿主程序。宿主程序可以使用 QPainter 像绘制普通位图一样将网页内容自由组合到任意图层之下，从根本上解决层级剪裁与遮挡问题。

1.2 POC 目标与非目标 (Scope & Non-Goals)

维度 POC 包含的目标 (In-Scope) 明确排除的非目标 (Non-Goals)
承载形态 在 ListViewDebugPanel (专属调试面板) 中新增独立的 CEF 离屏预览页，完全隔离主程序运行风险。 暂不修改主桌面 ListView::paintEvent，不替换主桌面现有 10 个标准组件的运行机制。
核心指标验证 验证 CEF 离屏模式下的 Alpha 透明通道、60fps 流畅度 以及 基础鼠标点击/移动交互。 暂不进行复杂的键盘输入法 (IME) 候选框嵌入、跨进程多显示器 DPI 动态热插拔适配。
通信与桥接 仅提供基础的页面加载、Console 日志输出与简单的交互通知。 暂不推倒重构现有的 window.desktop / 双级 postMessage IPC 协议栈。
壁纸系统 专注组件离屏能力的有效性验证。 暂不触动 LinWallpaperWebViewRuntime 现有网页壁纸体系。

2. 目录规范与依赖拓扑

2.1 3rdparty/cef 目录结构

为确保依赖管理的清晰透明，避免不透明的后台下载行为，在项目根目录下规范定义 3rdparty/cef 目录。该目录通过 .gitignore 忽略，避免大体积二进制污染 git 仓库。 

LinDesk/
├── 3rdparty/
│   └── cef/
│       ├── include/               # CEF 官方 C++ 头文件 (cef_app.h, cef_client.h 等)
│       ├── libcef_dll/            # CEF C++ Wrapper 接口源码或头文件
│       ├── Release/               # 运行时动态库与资源文件
│       │   ├── libcef.dll         # Chromium 核心动态库 (~150MB)
│       │   ├── icudtl.dat         # Unicode 国际化数据包
│       │   ├── v8_context_snapshot.bin
│       │   └── locales/           # 本地化资源目录 (zh-CN.pak, en-US.pak 等)
│       ├── lib/
│       │   ├── libcef.lib         # 链接导入库
│       │   └── libcef_dll_wrapper.lib # C++ 包装静态库 (MSVC static runtime)
│       └── README.md              # 放置指引与版本说明
└── scripts/
    └── download_cef.ps1           # 可选的自动化下载与校验解压脚本

2.2 CMake 条件编译设计

在 CMakeLists.txt 中采用优雅降级 (Graceful Degradation) 设计：检测是否存在 3rdparty/cef 或 CEF_ROOT 环境变量。未放置 CEF 时，正常编译原生 LinDesk，完全零影响；一旦放置，自动激活 LINDESK_HAS_CEF 宏并参与编译。 

# --- CEF 离屏渲染 (OSR) 模块探测 ---
set(CEF_ROOT "$ENV{CEF_ROOT}" CACHE PATH "Path to CEF prebuilt binary directory")
if(NOT CEF_ROOT OR NOT EXISTS "${CEF_ROOT}")
    if(EXISTS "${CMAKE_CURRENT_SOURCE_DIR}/3rdparty/cef/include/cef_app.h")
        set(CEF_ROOT "${CMAKE_CURRENT_SOURCE_DIR}/3rdparty/cef")
    endif()
endif()

if(CEF_ROOT AND EXISTS "${CEF_ROOT}/include/cef_app.h")
    message(STATUS "Found CEF prebuilt SDK at: ${CEF_ROOT}")
    target_compile_definitions(LinDesk PRIVATE LINDESK_HAS_CEF)
    target_include_directories(LinDesk PRIVATE "${CEF_ROOT}" "${CEF_ROOT}/include")
    target_link_libraries(LinDesk PRIVATE 
        "${CEF_ROOT}/lib/libcef.lib"
        "${CEF_ROOT}/lib/libcef_dll_wrapper.lib"
    )
    # 拷贝必要的 CEF 运行时文件至输出目录
    add_custom_command(TARGET LinDesk POST_BUILD
        COMMAND ${CMAKE_COMMAND} -E copy_directory
            "${CEF_ROOT}/Release"
            "$<TARGET_FILE_DIR:LinDesk>"
        COMMENT "Copying CEF runtime binaries and resources..."
    )
else()
    message(STATUS "CEF not found. CEF OSR POC will be disabled (LinDesk builds natively).")
endif()

3. CEF OSR 核心类架构设计

3.1 QTimer 外部消息泵模式

在 Qt 应用程序中集成 CEF，最稳定且不易发生跨线程死锁的方案是采用 外部消息泵 (External Message Pump)。

单线程协同调度原理

设置 CefSettings.multi_threaded_message_loop = false 与 CefSettings.external_message_pump = false。
通过 Qt 主线程的一个高精度定时器 QTimer（定时间隔 10ms），定期调用 CefDoMessageLoopWork()。
收益：CEF 的 UI 工作完全融入 Qt 主线程，Qt 绘制事件、CEF OnPaint 回调和鼠标事件都在同一线程上下文中，零多线程竞态，异常崩溃风险极低。

3.2 核心类职责划分

类名 基类 / 接口 核心职责
CefOsrApp CefApp 配置浏览器进程参数（关闭沙箱、启用硬件加速）、管理资源协议、指定子进程路径。
CefOsrClient CefClient, CefLifeSpanHandler 管理单个 CEF 浏览器的生命周期，分发 OnAfterCreated 和 DoClose 事件。
CefOsrRenderHandler CefRenderHandler 实现 GetViewRect 同步视口尺寸；
实现 OnPaint 捕获 32 位 BGRA 内存缓冲，并封装发射给 Qt 视图。
CefOsrWidget QWidget Qt 可视化承载控件；
维持 QTimer 调度 CefDoMessageLoopWork()；
在 paintEvent 中用 QPainter::drawImage 呈现网页；
捕获鼠标事件换算坐标后调用 CefBrowserHost::SendMouse...。

3.3 OnPaint 到 QPainter 渲染管线

CEF 离屏渲染在页面有任何变动时触发 CefRenderHandler::OnPaint。我们在此回调中将原始像素封装为 QImage： 

void CefOsrRenderHandler::OnPaint(CefRefPtr<CefBrowser> browser,
                                 PaintElementType type,
                                 const RectList& dirtyRects,
                                 const void* buffer,
                                 int width,
                                 int height)
{
    // CEF 导出的 buffer 为 32 位 BGRA 格式，完美对应 QImage::Format_ARGB32_Premultiplied
    QImage frame(static_cast<const uchar*>(buffer), width, height, QImage::Format_ARGB32_Premultiplied);
    
    // 浅拷贝（深拷贝像素数据以供 QWidget 安全绘制）
    QImage frameCopy = frame.copy();

    // 通知绑定的 Qt 宿主控件更新
    if (m_hostWidget) {
        m_hostWidget->updateFrame(frameCopy);
    }
}

void CefOsrWidget::paintEvent(QPaintEvent* event)
{
    QPainter painter(this);
    if (!m_currentFrame.isNull()) {
        // 直接在当前 QWidget 表面绘制带有 Alpha 透明通道的网页画面
        painter.drawImage(rect(), m_currentFrame);
    }
}

3.4 鼠标交互注入机制

CefOsrWidget 重写 Qt 的鼠标事件，转换为 CEF 对应的事件结构并注入浏览器宿主： 

void CefOsrWidget::mouseMoveEvent(QMouseEvent* event)
{
    if (m_browser && m_browser->GetHost()) {
        CefMouseEvent mouseEvent;
        mouseEvent.x = event->x();
        mouseEvent.y = event->y();
        mouseEvent.modifiers = getCefModifiers(event->modifiers());
        m_browser->GetHost()->SendMouseMoveEvent(mouseEvent, false);
    }
}

void CefOsrWidget::mousePressEvent(QMouseEvent* event)
{
    if (m_browser && m_browser->GetHost()) {
        CefMouseEvent mouseEvent;
        mouseEvent.x = event->x();
        mouseEvent.y = event->y();
        mouseEvent.modifiers = getCefModifiers(event->modifiers());
        CefBrowserHost::MouseButtonType btn = (event->button() == Qt::RightButton) ? MBT_RIGHT : MBT_LEFT;
        m_browser->GetHost()->SendMouseClickEvent(mouseEvent, btn, false, 1);
    }
}

4. 调试面板集成与验证用例

4.1 透明动态测试页规格 (test_clock.html)

在项目的资源目录中提供专用的测试页面 installer/cef_test/test_clock.html，专门用于检验离屏模式的核心表现：

  • 透明背景：body { background: transparent; }，检验是否存在黑底或白边渲染瑕疵；
  • 60fps 高频动画：包含一个持续平滑旋转的渐变罗盘和指针动效，检验 OnPaint 刷新频率与帧率平稳性；
  • 交互式按钮与计数器：包含可点击的交互按钮，点击后数字自增并改变背景色，用于验证鼠标按下、释放与悬停的响应延迟。

4.2 ListViewDebugPanel 测试标签

在现有的 ListViewDebugPanel 导航栏中增加 「CEF OSR POC」 选项卡。当点击该标签时，右侧展示 CefOsrWidget 容器，并附带控制栏（刷新、DevTools 打开、实时帧率统计显示）。

5. 实施里程碑路线图

1 里程碑一：目录结构规范与 CMake 模块探测 依赖准备

建立 3rdparty/cef 目录结构规范，创建 scripts/download_cef.ps1，在 CMakeLists.txt 中编写 LINDESK_HAS_CEF 条件探测逻辑，保证不影响常规构建。

2 里程碑二：CEF OSR 基础类实现与外部消息泵接入 核心实现

在 src/desktop/widgets/cef/ 下实现 CefOsrApp、CefOsrClient、CefOsrRenderHandler 与 CefOsrWidget，打通 CefDoMessageLoopWork 与 OnPaint 像素转换。

3 里程碑三：集成至 ListViewDebugPanel 与测试用例验证 调试验证

在 ListViewDebugPanel 中添加专用标签页嵌入 CefOsrWidget，加载 test_clock.html，在真机上验证透明通道、60fps 动效与点击交互。

4 里程碑四：性能与资源消耗评审及决策输出 总结评估

测量 CEF OSR 运行时的内存峰值、CPU 占用、安装包体积膨胀率，形成完整的评估数据，供最终决定是否将主桌面组件系统迁移到 CEF。
