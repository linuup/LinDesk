LinDesk 移除 WebView2 方案 · 改造任务书

面向：antigravity（执行者） 性质：信息盘点与改造计划（未改动任何代码） 整理日期：2026-10-12

1. 任务背景与目标

LinDesk 的 LinWidget 桌面小组件系统原本使用 WebView2（Edge WebView2 Runtime）渲染 HTML 组件（组件包 + 共享宿主进程式运行时 + 动态壁纸）。近期项目已切换为 CEF OSR（Chromium Embedded Framework 离屏渲染）作为组件渲染方案。

本次任务目标：

  1. 彻底移除 WebView2 方案：构建链接、运行时类、共享宿主逻辑、设置界面中的 WebView2 分支、宿主页面资源。
  2. 保留原 HTML 组件系统的全部功能：组件包加载、组件生命周期、布局、权限、注册表、配置持久化、消息通信、设置对话框、开发模式、组件资源。移除 WebView2 后，这些能力必须按原有接口继续工作，仅渲染引擎替换为 CEF OSR（功能保留清单见第 6 节）。
  3. 只清理 WebView2 相关代码路径，不改组件系统功能语义。

硬约束：当前 CEF OSR 路径只实现了"帧渲染"，尚未实现 JS↔C++ 消息桥（见第 7 节关键缺口）。移除 WebView2 前必须补齐或确认 CEF 侧等价桥，否则组件与主程序的通信（设置变更、系统信息、存储等）会中断。

2. 现状总览：双渲染栈并存

代码中两套渲染路径同时存在，由 WidgetManager::m_cefOsrEnabled（配置项 LinWidgets/CefOsrEnabled，默认 true）与 LINDESK_HAS_CEF 宏控制分流：

维度CEF OSR（新方案，保留）WebView2（旧方案，移除）
运行时LinCef::CefOsrBrowserInstance（每组件一个实例）+ CefOsrRenderHandlerLinWidgetWebViewRuntime（共享运行时 + 子窗口）+ LinWallpaperWebViewRuntime（壁纸）
渲染呈现离屏帧 QImage → LinWidgetCanvasWidget 帧缓冲 → ListView::paintEvent 合成绘制WebView2 Composition Controller，原生分层子窗口（SetParent 嵌入/浮动）
JS 消息桥未实现（0 处桥接代码）chrome.webview.postMessage → LinWidgetWebViewRuntime::handleWebMessageJson → WidgetManager::handleRuntimeMessage
壁纸无 CEF 实现；CEF 启用时会强制停用壁纸（stopWallpaper(true)）LinWallpaperWebViewRuntime 实现动态壁纸
入口分流launchWidgetInstance：m_cefOsrEnabled && CefManager::isCefAvailable() 时走 CEF否则走 ensureSharedHost + sendAddWidgetToSharedHost（fallback）

结论：CEF 已是主渲染路径，WebView2 目前只是 fallback 与壁纸实现。移除的改动面清晰、可控。

5. 渲染承载架构与本地资源加载

组件如何被 CEF "装"起来渲染，有两种承载思路。当前代码采用前者（5.1）；后者（5.2）为讨论过的备选方向，记录在案供决策参考。5.3 为本地资源跨目录加载的引擎对应方案。

5.1 承载方式（现状）：每组件一个独立 OSR 实例

与旧 WebView2 "把所有组件塞进一个共享宿主 HTML" 不同，CEF OSR 架构下每个运行的小组件拥有独立干净的 CefOsrBrowserInstance：

  • 每个实例按自身 geometry 离屏渲染（create(entryUrl, geometry)），组件间不共享 DOM / JS 上下文。
  • frameReady 信号输出 QImage 帧，直接推送到 LinWidgetCanvasWidget 的帧缓冲区。
  • ListView::paintEvent 按嵌入 / 浮动层级把各组件帧合成到桌面（多图层合成）。

第一阶段验收标准：在 Debug 面板或设置中点击"加载时钟 / 天气小组件"，CEF OSR 能立刻成功渲染出该组件的完整画面，并浮现在桌面图标下方。

5.2 备选方向（已讨论，未作为当前路线）：单宿主页 + 每组件一个 iframe

讨论中提出的方案：一个常驻 CEF 实例承载宿主页，页面内每个组件用 <iframe> 标签挂载（src 直接指向组件 entry 页）。此方向与旧 WebView2 共享宿主模型同构，但当前迁移路线按 5.1 的独立实例推进。对比：

维度每组件一个 OSR 实例（5.1，采用）单宿主页 + iframe（5.2，备选）
渲染进程N 个组件 = N 个渲染进程（隔离强；内存随组件数线性增长）1 个渲染进程（省内存；宿主页崩溃 = 全部组件挂，需页面级恢复机制）
消息桥按实例各做一套；当前 0 实现（见第 7 节）宿主页一套桥，按 widgetId 分发，实现一次
组件包兼容直接加载 entry 页面，零改包iframe src 直接指向 entry，零改包
故障隔离单组件崩溃不影响其他单点故障，需崩溃恢复
输入路由按 widgetId 查实例（现成）按坐标命中 iframe（需新增）
本地资源跨目录各实例独立加载，需统一 scheme 映射（见 5.3）iframe 同源策略下同样需虚拟主机映射

iframe 与 Web Component 的区别（选型依据）：iframe 是独立文档（独立 DOM / JS 全局 / 样式隔离），src 直接指向组件包 entry 页，天然匹配"组件包 = 独立页面"的模型；Web Component（custom element + shadow DOM）是同一文档内的封装，共享 JS 全局、隔离弱，且需把 11 个组件包改造成自定义元素，侵入大。因此若未来改走单宿主页方向，承载标签也应选 iframe。

5.3 本地资源加载与跨域方案（WebView2 → CEF 对应实现）

环节说明
原 WebView2使用 SetVirtualHostNameToFolderMapping，将本地路径映射为虚拟域名（如 https://widget-clock.linwidget.local/），避免本地 file:// 跨域与 CORS 限制。
CEF 对应实现实现 CefResourceRequestHandler 或注册自定义 Scheme（如 linwidget://）：当网页请求组件资源或图片时，由 C++ 直接从本地目录读取对应文件流返回，确保组件能正常加载本地图片、字体和相对路径 JS。

注意：5.3 是组件在 CEF 下正常显示的前置条件之一——组件 entry 页及其内部相对路径资源（图片 / 字体 / JS）必须能跨目录访问，否则页面可能只出骨架。

7. 关键缺口：CEF 侧 JS 消息桥未实现 必须先补

全库检索结果（OnProcessMessageReceived | CefMessageRouter | RunJavaScript | executeJavaScript | OnQuery | V8Handler | GetV8Context）：0 匹配。即 CEF 路径当前只有"帧渲染"（页面画出来），没有 JS 与 C++ 的双向消息通道。

而组件系统依赖消息桥：

  • Notes 组件（script.js、settings.html）直接调用 chrome.webview.postMessage(...) 与 chrome.webview.addEventListener('message', ...) —— WebView2 专有 API。
  • WebView2 路径的消息流向：组件 JS → chrome.webview → LinWidgetWebViewRuntime::handleWebMessageJson → WidgetManager::handleRuntimeMessage → 系统信息 / 存储 / 实例管理响应。

依赖消息桥、删除 WebView2 后会受影响的功能（必须由 CEF 桥接管）：

  • 组件设置变更通知（Notes 的 linwidget_settings_changed_request）——WidgetMessageType::ThemeChanged / OpenWidgetSettings 类消息。
  • 系统信息请求 / 订阅 / 推送（system_info_request / system_info_response / system_info_update，WidgetManager 的 handleSystemInfoRequest / sendSystemInfoUpdate）。
  • 组件存储（storage_request / storage_response，handleStorageRequest）。
  • 实例管理（create_widget_instance_request/response、close/remove/list）。
  • 布局 / 几何同步（widget_geometry_changed、update_widget_geometry）、move / resize / close 指令。

移除 WebView2 的后果：chrome.webview 对象不复存在；若 CEF 侧不实现等价桥（例如 CEF Query / executeJavaScript + 注入桥对象，或用 OnProcessMessageReceived 与子进程通信），则上列交互全部失效。建议顺序：先补 CEF 消息桥并逐项验证组件功能（第 6 节矩阵），再删 WebView2。

8. 风险与注意事项

  1. 壁纸功能将不可用：动态壁纸目前只有 WebView2 实现（LinWallpaperWebViewRuntime），CEF 无替代。现状：CEF 启用时壁纸已被强制停用（setCefOsrEnabled 内 stopWallpaper(true)）。移除 WebView2 后壁纸配置入口应一并处理（禁用或提示"暂不支持"），或后续用 CEF 重新实现。
  2. 组件 JS 兼容：除 Notes 外，其余组件（Timer 等）主要用页面内 postMessage（Worker/self 通信）而非 WebView2 桥；需逐个确认组件包的桥依赖面。
  3. default_page.html 复用：被 CEF 引用，勿删；删除任何 LinWidgetRuntime 文件前先全局核对引用。
  4. 回退路径删除后的行为：launchWidgetInstance 的 else 分支移除后，若 CEF 初始化失败（SDK 缺失、LINDESK_HAS_CEF 未定义），组件启动应明确报错而非静默失败。
  5. 构建环境：移除 WebView2 后，.nuget/packages/microsoft.web.webview2 依赖不再需要；CEF 依赖 3rdparty/cef（scripts/download_cef.ps1 获取）。

9. 迁移路线图（4 阶段计划）

在完成"能把小组件完整显示出来"（第一阶段）之后，后续按序推进。顺序原则：先让组件系统的功能在 CEF 上完整可用，再清理 WebView2 代码，避免出现"渲染换过来了、交互却断了"的中间态。

[第一阶段：呈现]   本地小组件包加载与渲染 -> 独立 OSR 实例驱动多组件 -> Canvas 多图层合成
                            │
                            ▼
[第二阶段：通信]   搭建 C++ 与 JS 的双向消息桥（CefMessageRouter / window.cefQuery / linwidget API）
                            │
                            ▼
[第三阶段：交互]   鼠标点击穿透/捕获 -> 组件拖拽移动（widget:drag）-> 缩放与层级改变
                            │
                            ▼
[第四阶段：外围治理]  组件权限隔离（网络/存储权限）-> 控制台日志捕获 -> 生命周期监控与热重载

第一阶段：呈现（当前进度）

  • 本地小组件包加载与渲染；独立 OSR 实例驱动多组件；Canvas 多图层合成（详见第 5.1 节）。
  • 验收标准：在 Debug 面板或设置中点击"加载时钟 / 天气小组件"，CEF OSR 立刻成功渲染出完整画面并浮现在桌面图标下方。
  • 前置条件：本地资源加载与跨域方案（第 5.3 节，CefResourceRequestHandler / 自定义 scheme）确保组件包内图片、字体、相对路径 JS 可加载。

第二阶段：通信（JS ↔ C++ 双向消息桥）

  • 原 WebView2 用 chrome.webview.postMessage 派发事件；CEF 迁移使用 CefMessageRouterBrowserSide（或 V8 注入）。
  • 向前端暴露 window.linwidget = { postMessage: ... }，使小组件内部调用天气 API、保存便签数据、读取系统状态的指令能够发送到 Qt WidgetManager。
  • 此阶段即第 7 节"关键缺口"的补齐工作；补桥后按第 6 节功能矩阵验证组件交互（重点 Notes）。

第三阶段：交互（事件路由与拖拽定位）

  • 将 ListView 捕获的鼠标按下 / 移动 / 抬起事件，根据 canvasWidget->widgetAt(pos) 精准路由到目标组件。
  • 迁移组件拖拽移动机制：前端发出移动指令（widget:drag）时，Qt 更新该组件在桌面的 geometry，并同步持久化到 layout.json。
  • 缩放与层级改变（zOrder）随同处理。

第四阶段：外围治理（权限与生命周期）

  • 迁移安全沙箱：限制无网络权限的小组件发起外部 fetch。
  • 拦截并收集组件的 console.log，输出到调试面板的日志查看器。
  • 恢复组件异常崩溃后的自动重启与热重载（Auto-Reload）。

与各阶段并行 / 收尾的 WebView2 清理

  1. CMake：删除 LINDESK_WEBVIEW2_ROOT 探测、LINDESK_HAS_WEBVIEW2 宏、WebView2LoaderStatic.lib 链接与 POST_BUILD 拷贝。
  2. 删除 WebView2 运行时类：LinWidgetWebViewRuntime.*、LinWallpaperWebViewRuntime.*。
