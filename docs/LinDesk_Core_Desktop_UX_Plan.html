LinDesk 桌面核心功能体验优化方案与路线图

定位：人机工学交互、视觉微动画、操作跟手感专项优化 对标：Stardock Fences 5、腾讯桌面整理、Windows 11 原生交互 更新：2026-10-30

1. 现状诊断与核心目标

LinDesk 已经完成了底层桌面的核心技术架构（包括桌面底座嵌入、壁纸同步渲染、LinBox 容器化、Win11 原生上下文菜单适配与 CEF 小组件运行时）。在最新的启动重构中，通过冷启动同步壁纸解码和 Box 首帧同频布局，彻底消除了启动闪烁和 80ms 刷新隐匿的问题。

但在日常高频操作的人机工学细节上，仍存在若干与商业级标杆软件脱节的痛点：

  • 动画生硬：盒子折叠展开为瞬切尺寸（setFixedHeight），隐藏桌面图标为直接刷新消失，缺乏现代流体动效；
  • 排版对齐费力：盒子移动时缺少与屏幕边缘及其他盒子的磁吸（Snap），多个盒子对齐或贴边需要反复手动微调；
  • 键盘直觉缺失：不支持在桌面上盲打首字母快速选中文件（Type-to-Select），误删/误移动后缺少 Ctrl + Z 撤销机制；
  • 海量文件与图标加载卡顿：桌面图标较多或映射几百个文件的文件夹时，主线程同步提取图标导致界面假死；
  • 高阶收纳功能空白：缺少 Fences 标志性的“悬停自动展开 (Auto-Peek / Roll-up)”与真正实用的“一键桌面智能分类整理”。

核心目标：从“功能可用”迈向“商业级高品质交互”，消除机械生硬感与主线程卡顿，让桌面具备极致的整洁感与顺滑的操作手感。

2. 核心功能深度优化方案

维度一：桌面盒子 (LinBox) 交互质感与高阶能力

1.1 折叠 / 展开的弹性高度缓动动画

现状痛点：点击右上角折叠按钮时，直接调用 setFixedHeight(m_titleHeight)，窗口高度瞬间突变，视觉跳跃感严重。

优化方案：

  • 引入 QVariantAnimation（时长 180ms ~ 220ms，缓动曲线使用 QEasingCurve::OutCubic）；
  • 展开流程：先平滑展开高度，内部内容区域（m_scrollArea）随高度扩展平滑淡入（Fade In）；
  • 收起流程：内容区域先行微渐隐，随后高度平滑回卷至标题栏高度；
  • 涉及文件：src/box/LinBox.cpp 中的 toggleCollapse()。

1.2 双击标题栏折叠 与 悬停自动展开 (Roll-up / Auto-Peek)

现状痛点：用户必须精确瞄准右上角 14px 的折叠按钮才能操作；折叠后的盒子取用文件需要手动展开再手动收起，步骤繁琐。双击区域冲突（本次规范重点）：当前 LinBox.cpp:1836-1845 中，双击标题栏的"文本矩形"（mappedTitleTextRect() 返回整条标题栏带，非映射 Box 为左右各缩 35px 的全宽）会触发标题重命名——即双击标题栏几乎任何位置都进入"自定义名称"编辑，与折叠目标冲突，必须先规范双击命中区域。

优化方案：

  • 双击位置分区规范（先行落地）：标题栏按命中优先级分四区——
    1. 按钮区（m_collapseBtn / m_viewSwitchBtn 的 geometry）：交按钮自身 click 处理（折叠 / 视图切换），双击不拦截；
    2. 映射图标区（仅 MapBox，mappedTitleIconRect）：双击在资源管理器中打开映射文件夹（保留现状行为）；
    3. 标题文本热区（缩窄后的 mappedTitleHitRect）：仅"实际绘制文本宽度 + 左右各 scaledPx(8) 的 padding"范围命中，双击进入重命名（自定义名称）——不再整条标题栏触发；
    4. 其余空白区：双击调用 toggleCollapse() 折叠 / 展开。
  • 文本热区计算：新增 mappedTitleHitRect()（复用 displayTitleText() + QFontMetrics::horizontalAdvance 的 elided 宽度；非映射 Box 水平居中于标题栏，映射 Box 从 mappedTitleIconRect().right() + scaledPx(7) 起算）。绘制逻辑（mappedTitleTextRect）与命中热区分离，避免"视觉文字在中间、双击判定却全宽"的偏差；
  • 边界处理：双击空白折叠前若 m_titleEdit->isVisible() 先 commitTitleEditing()；折叠状态双击空白同样走 toggleCollapse() 双向展开；正处于标题编辑 / 框选态时不响应双击，交回默认；双击事件内先重置 m_isMoving=false，避免与标题栏拖拽移动互扰；
  • 悬停自动展开 (Roll-up)：折叠状态下鼠标光标悬停标题栏达到 150ms 后盒子自动下卷平滑展开；鼠标移出整个盒子区域且无拖拽行为后延时 250ms 平滑收回折叠；
  • 客户价值：用户日常可将所有盒子折叠成漂亮的"抽屉标签栏"，桌面整洁到极致，使用时双击空白区或悬停即现；重命名只命中文字本身，两者互不误触。

1.3 移动盒子磁吸与对齐吸附 (Magnetic Snapping)

现状痛点：拖拽移动盒子或拉伸尺寸时无吸附能力，并排摆放两个盒子很难对齐，贴近屏幕边缘也很难精准贴合。

优化方案：

  • 吸附阈值设为 kSnapThreshold = 10px；
  • 边缘吸附：检测屏幕可用工作区四周（左、右、顶、任务栏上边缘）；
  • 同类吸附：检测同屏其他可见 LinBox 的四边（Left, Right, Top, Bottom）；
  • 当拖拽位移接近吸附线时产生微阻尼并自动对齐坐标，支持按住 Alt 键临时关闭吸附自由摆放；
  • 涉及文件：src/box/LinBox.cpp 的 mouseMoveEvent 移动分支。

1.4 真正的一键智能分类整理 (Smart Auto-Organization)

现状痛点：当前右键菜单的“整理桌面”本质只是字母名称排序；新建 Box 后必须逐个挑文件拖入，初次使用成本高。

优化方案：

  • 一键整理自动建立或复用标准盒子：快捷方式、文件夹、常用文档、压缩包与安装包；
  • 自动将散落在桌面的文件按类型归集至相应盒子，保留桌面原生固定项（此电脑、回收站）；
  • 支持规则设置（例如“新保存到桌面的文档自动进入文档盒子”）；
  • 涉及文件：src/desktop/ListView_Actions.cpp。

维度二：桌面图标交互与键盘原生直觉

2.1 盲打首字母跳选定位 (Type-to-Select)

现状痛点：在原生 Windows 桌面按下键盘字符（例如按 w 键）会立即选中 WeChat。目前 LinDesk 忽略了普通字符按键，键盘党无法快速选文件。

优化方案：

  • 在 ListView::keyPressEvent 中维护按键缓冲区和 600ms 超时计时器；
  • 收集用户键入的字符序列（如 "chr" 或单字母 "v"），遍历桌面项目并在 displayName 及拼音首字母中检索匹配项；
  • 命中后直接高亮选中该项并赋予焦点，连续敲同字母在同首字母项之间轮询切换。

2.2 全局撤销快捷键 (Ctrl + Z) 支持

现状痛点：在桌面发生误删、误移动文件后，按 Ctrl + Z 无反应，缺少误操作救回机制。

优化方案：

  • 在 ListView::keyPressEvent 中拦截 QKeySequence::Undo；
  • 桥接 Windows Shell Undo 栈或执行 LinDesk 文件操作的反向操作，实现安全兜底。

2.3 双击空白隐藏桌面与淡入淡出动效 (Fade Transition & Settings Switch)

现状痛点：双击空白处隐藏/显示桌面时为瞬时重绘（硬切刷新），视觉跳变突兀生硬；同时，用户对“双击空白是否触发隐藏”以及“是否启用淡入淡出动画”缺乏清晰可控的设置面板入口，容易产生误触或动效偏好无法满足的问题。

优化方案与详细规范：

  • 设置页独立开关控制（本次规范核心）：
    • 开关一 · 双击隐藏桌面图标 (DoubleClickHideIcons)：
      • 界面位置：设置中心 -> 桌面与行为 (Desktop & Behavior) 页面，卡片标题为“双击隐藏桌面图标”，副标题为“双击桌面空白处快速隐藏或显示所有桌面图标与整理盒子”；
      • 配置项持久化：写入 config.ini 的 [Desktop] DoubleClickHideIcons=true/false；默认值为 true；
      • 双向实时同步：设置页开关状态与桌面右键上下文菜单（查看 -> 双击隐藏图标）保持实时双向绑定，一处修改立即全局生效并持久化；关闭后，彻底屏蔽空白双击隐藏逻辑，避免高频双击误触。
    • 开关二 · 隐藏/显示淡入淡出动效 (FadeTransitionOnHide)：
      • 界面位置：紧随上述开关下方，作为视觉动效专属性开关，标题为“隐藏桌面动效过渡”，副标题为“隐藏或恢复桌面元素时播放平滑的淡入淡出透明度过渡动画”；
      • 配置项持久化：写入 config.ini 的 [Desktop] FadeTransitionOnHide=true/false；默认值为 true；
      • 关闭回退机制：若用户关闭动效开关（追求瞬时响应或低配机器省电），则直接走无延迟的瞬时显隐切换（兼容现状行为）。
  • 淡入淡出动效设计与实现细节：
    • 动画驱动机制：在 ListView_Actions.cpp 中引入 QVariantAnimation，驱动统一透明度变量 m_desktopHideOpacity（范围 0.0f ↔ 1.0f）；
    • 动效参数：过渡时长 180ms ~ 220ms，采用平滑三次缓动曲线 QEasingCurve::InOutQuad；
    • 全元素同频过渡：淡出时，桌面普通图标、Box 盒子容器及选中框等桌面层元素同频渐隐至 0.0，优雅透视露出底层纯净壁纸/动态小组件；淡入时平滑反向淡入至 1.0；
    • 状态机与防抖保护：
      1. 连击防抖与动画拦截：在动效执行期间（m_fadeAnimation->state() == QAbstractAnimation::Running），再次双击桌面空白处直接被拦截忽略，严防因手抖极速连击导致透明度状态机错乱或闪烁；
      2. 输入穿透控制：当透明度处于淡出完成态（隐藏态，m_desktopHideOpacity == 0.0f）时，桌面图标区域自动禁用鼠标命中与拖拽框选，仅响应双击空白恢复或右键菜单呼出；
      3. 首帧与脏区刷新：每帧动画仅触发桌面脏区 update()，动效完全结束后触发 syncBoxVisibilityWithDesktopIcons() 并保存布局状态。
  • 涉及核心文件：
    • src/ui/SettingUI.cpp / SettingUI.h：在桌面设置页添加设置卡片与 FluentToggleSwitch 开关；
    • src/desktop/ListView.h / ListView.cpp：维护动效开关状态、双击命中分支与鼠标事件门禁；
    • src/desktop/ListView_Actions.cpp：实现 onMenuShowDesktopIcons() 中的淡入淡出动画管线；
    • src/desktop/RightMenu.cpp：同步维护右键菜单勾选项；
    • src/services/LayoutPersistenceService.cpp：配置项 DoubleClickHideIcons 及 FadeTransitionOnHide 的读取与写盘。

2.4 图标与 IO 管线：两级 LRU 缓存与异步渐进式加载 (Two-Tier Icon Cache & Progressive Loading)

现状痛点：当用户桌面图标较多（100+），或在 LinBox 中映射了包含数百个文件的深层目录（如“下载”、“文档”或移动硬盘）时，主线程在 ListItemData.h 中同步调用 Windows SHGetFileInfoW、GetShellThumbnail 以及图标抠图算法。密集的同步磁盘 I/O 和 COM 耗时会导致桌面初始化或文件夹打开时产生明显的假死与界面掉帧，且相同扩展名/相同目标无法共享图标实例。

优化方案与详细规范：

  • 内存级 LRU 缓存（第一级）：
    • 引入全局单例图标缓存池 IconCacheManager，以 (filePath + lastModifiedTime + iconSizeTier) 作为唯一哈希键（针对特殊文件夹以 PIDL / CLSID 缓存）；
    • 相同文件类型或未修改的文件二次加载命中率达 100%，内存中直接复用同一份 QPixmap 引用，不仅耗时降为 0ms，还能大幅压缩海量图标带来的 GDI 与内存占用；
    • 设置合理的上限阈值（如最多缓存 500 个高分辨率图标对象），遵循 LRU 机制淘汰最近最少使用的图标。
  • 后台异步解码与渐进式淡入（第二级）：
    • 首帧占位（Skeleton / Fallback）：主线程扫描到新文件时，先以 0ms 极速返回系统通用的轻量类型图标（如通用文档、通用文件夹底图），确保列表秒级排版上屏，绝不阻塞主线程绘制；
    • 线程池异步提取：将重度的高清 Shell 图标抽取、256x256 文件夹 Live Preview 缩略图生成及 Alpha 边缘去黑边计算分发给后台 QThreadPool 异步工作线程；
    • 平滑淡入替换 (Progressive Fade-In)：后台线程解码完成后，向主线程发送信号，仅对发生变动的局部图标项触发 100ms 的平滑透明度淡入替换（Fade-In），用户肉眼感知上既不卡顿，又呈现出极具科技感的流体加载效果。
  • 涉及核心文件：
    • src/models/data/ListItemData.h：解耦同步提取流程，接入图标缓存池查询与异步提取任务分发；
    • src/services/IconCacheManager.h / .cpp（新增）：轻量级线程安全的高速两级 LRU 图标缓存管理器；
    • src/services/SysInfoUtil.cpp：后台线程异步调用缩略图生成与裁切。

维度三：拖拽交互手感与视觉反馈

3.1 拖入 Box 的边界呼吸光晕高亮 (Drop Target Accent Glow)

现状痛点：拖拽文件悬停在各个 Box 上方时，仅有光标文字提示，盒子容器本身缺乏明显的投掷响应。

优化方案：在 LinBox::dragEnterEvent 与 dragLeaveEvent 维护投掷悬停状态，在 Box 边框渲染一圈柔和的发光外边框（Accent Color Glow），明确反馈落入目标。

3.2 多文件拖拽层叠缩略图与数字角标 (Drag Badge)

现状痛点：框选多个文件拖动时缺少数量反馈。

优化方案：拖拽生成最多 3 张微倾斜的层叠图标阴影，并在右下方绘制药丸状数字角标（如 +6），对齐 Windows 11 视觉质感。

维度四：多显示器与多屏幕扩展支持

现状痛点：代码中深度写死了 primaryScreen()->geometry()，在扩展双屏场景下，副屏无法自如摆放 Box 或进行网格布局。

优化方案：将视口扩展至 virtualGeometry()，支持盒子在多屏幕之间自由拖拽与持久化坐标，覆盖多屏白领与开发者的重度需求。

维度五：性能、空闲功耗与“零打扰”静默体验

全屏独占游戏 / PPT 放映免打扰休眠：检测到前台存在独占全屏窗口时，LinDesk 自动挂起所有桌面小组件刷新与后台定时器，CPU/GPU 占用严格降为 0.0%，杜绝游戏抢帧和笔记本耗电。
