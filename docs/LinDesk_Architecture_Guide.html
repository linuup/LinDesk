LinDesk 架构指南

版本：CEF OSR 版（替代旧 WebView2 架构指南） 依据：src 源码只读盘点 + 改造任务书 更新：2026-10-12

1. 系统总体定位与技术栈

LinDesk 是一款面向 Windows 平台的桌面整理与小组件增强软件：在系统桌面上叠加一层自绘桌面（图标管理、收纳盒 LinBox），并以 HTML 组件系统（LinWidget）在桌面直接渲染信息小组件。

层次技术 / 库职责
宿主核心C++ / Qt Widgets、CMake、vcpkg进程生命周期、桌面宿主嵌入（WorkerW）、事件调度、设置与更新。
桌面交互Qt Widgets、GDI/D2D全屏自绘画布、图标网格布局、框选、右键菜单、LinBox 收纳盒。
组件渲染CEF（Chromium）离屏渲染 OSRLinWidget 组件像素帧离屏渲染，统一绘制管线合成到桌面。
旧渲染栈WebView2（Edge）移除中旧组件渲染与动态壁纸实现；见改造任务书。
组件生态HTML5 / CSS / JS（组件包）10 个内置组件（时钟、监控、天气、便签、待办等）。

2. 桌面底座与统一绘制架构

2.1 桌面挂载（WorkerW）

LinDesktop 通过 Win32 挂载到系统桌面：向 Progman 发送 0x052C 消息拆分 WorkerW，找到 SHELLDLL_DefView 下方的 WorkerW 句柄，SetParent(linDesktopHwnd, workerWHwnd) 嵌入，与系统桌面同生共灭。

2.2 三层统一绘制管线

桌面呈现采用单条 QPainter 绘制管线（不再依赖原生子窗口 HWND 层级，避免遮挡与 UpdateLayeredWindowIndirect 报错）：

+-------------------------------------------------------+
|  1. 静态系统壁纸（LinDesktop 背景绘制）                  |
+-------------------------------------------------------+
                           |
+-------------------------------------------------------+
|  2. CEF OSR 小组件画布（LinWidgetCanvasWidget）         |
|     - renderCanvas(painter, dirtyRegion)              |
|     - 无组件时：default_page.html 毛玻璃引导卡片        |
|     - 有组件时：各组件 OSR 帧按图层合成                 |
+-------------------------------------------------------+
                           |
+-------------------------------------------------------+
|  3. 桌面图标与收纳盒（ListView / LinBox）               |
|     - 图标渲染数据缓存、框选、重命名、高亮              |
+-------------------------------------------------------+

ListView::paintEvent 按嵌入/浮动模式调整组件画布与图标层的先后：嵌入模式组件画布先画（组件在图标下方），浮动模式后画（组件在图标上方）。

2.3 防抢占与自愈

  • 桌面宿主窗口监听（startDesktopHostWindowMonitor）：监测 EVENT_OBJECT_CREATE / DESTROY。
  • 层级脱落时触发恢复（scheduleLinWidgetLayerRecovery / syncLinWidgetLayer）。

3. LinWidget 组件系统（核心维护重点）

3.1 承载方式：每组件一个独立 CEF OSR 实例

与旧 WebView2"单实例共享宿主"（所有组件塞进一个 host.html）不同，当前 CEF OSR 架构下每个运行的小组件拥有独立 CefOsrBrowserInstance：

  • 启动分流：WidgetManager::launchWidgetInstance 在 m_cefOsrEnabled && CefManager::isCefAvailable() 时 new CefOsrBrowserInstance(instanceId) → create(entryUrl, geometry)，存入 m_osrBrowsers。
  • 帧合成：frameReady(wid, geom, img, dirty) → LinWidgetCanvasWidget::updateWidgetFrame → ListView::paintEvent 的 renderCanvas。
  • 占位页：m_defaultOsrBrowser（__default_page__）加载 default_page.html，仅在无组件运行时显示。
  • 输入路由：鼠标/滚轮按 widgetId 查 m_osrBrowsers 转发（键盘/IME 为 P0 缺口，见任务书第 10 节）。

备选方向（已讨论未采用）：单宿主页 + 每组件一个 <iframe> 可省渲染进程数，但引入单点故障；当前路线按独立实例推进。

4. 消息协议与桥接

4.1 消息协议（WidgetMessageTypes）

src/desktop/widgets/linwidget/WidgetMessageTypes.h 定义字符串枚举 + makeWidgetMessage(type, widgetId)：launch / ready / error、组件几何（add_widget / update_widget_geometry / widget_geometry_changed / move / resize / close）、系统信息（system_info_request/response/update）、存储（storage_request/response）、实例管理（create/list/close/remove_widget_instance_*）、设置（open_widget_settings / theme_changed）。待规范化：无 requestId / 超时 / 错误码。

4.2 组件侧 API 目标形态（window.desktop）

组件加载后目标注入 window.desktop 桥对象（WebView2 时代由宿主脚本注入，CEF 时代经 injectBridgeScript 待实现）：

  • 身份与就绪：instanceId / widgetId / widgetName、await window.desktop.ready。
  • 几何控制：resizeWidget / setWidgetGeometry / setResizeUiVisible / openSettings。
  • 存储：storage.instance.set/get/remove/clear/all、storage.widget.*（跨实例共享）。
  • 系统信息（需 desktop 权限）：systemInfo.getSnapshot()、systemInfo.watch(cb, interval)。
  • 实例管理：instances.create/list、instance.close/remove。

4.3 传输层现状 缺桥

  • WebView2 时代：组件 JS → chrome.webview.postMessage → LinWidgetWebViewRuntime::handleWebMessageJson → WidgetManager::handleRuntimeMessage。
  • CEF 现状：全库检索 OnProcessMessageReceived | CefMessageRouter | RunJavaScript | executeJavaScript | OnQuery | V8Handler | GetV8Context = 0 匹配，桥未实现；Notes 组件仍在用 chrome.webview。
  • 结论：先补 CEF 消息桥（CefMessageRouterBrowserSide / V8 注入），再删 WebView2。

5. 数据持久化与存储拓扑

运行时配置位于用户配置目录（AppPaths 定义，%APPDATA%/LinDesk/ 下）：

%APPDATA%/LinDesk/
  ├── LinWidgets/
  │     └── registry.json        # 组件注册表 + 布局配置（AppPaths::linWidgetRegistryFilePath）
  ├── LinWidgetsData/            # 各组件数据仓储（AppPaths::linWidgetDataDir）
  └── LinWallpapers/             # 壁纸数据（AppPaths::userWallpapersDir）

组件布局（位置/尺寸/zOrder/可见性）经 ConfigManager 持久化，启动时 restoreFromConfig 恢复。
