ListView
只负责输入事件、状态管理、脏区管理、布局刷新、命中测试、右键菜单、拖拽逻辑

DesktopSceneSnapshot
渲染输入快照
把当前这一帧需要画的内容整理成统一数据结构

IDesktopRenderBackend
抽象渲染后端接口
定义所有渲染后端都要实现的方法

DesktopRasterRenderBackend
现有 QPainter 路线的后端
先把你现在的逻辑平移进去，作为基线实现

DesktopOpenGLRenderBackend
新的 OpenGL 后端
负责纹理缓存、批量绘制、动态层绘制

DesktopTextureCache
管图标纹理、文字纹理、静态内容缓存

DesktopRenderHost
一个宿主控件
根据设置选择 raster 或 OpenGL 后端，并承接真正的绘制调用

推荐类设计

先定义一个统一接口：

class IDesktopRenderBackend
然后两套实现：

class DesktopRasterRenderBackend : public IDesktopRenderBackend
class DesktopOpenGLRenderBackend : public IDesktopRenderBackend
建议新增的数据结构

你现在的 DesktopRootItemRenderData 很适合继续保留。
它已经是 item 级绘制数据。
但还缺一层“整帧快照”。

建议加：

struct DesktopOverlayRenderData
{
    QRect selectionRect;
    QRect insertionIndicatorRect;
    bool showSelectionRect = false;
    bool showInsertionIndicator = false;
};

struct DesktopSceneSnapshot
{
    QVector<const DesktopRootItemRenderData*> visibleDesktopItems;
    QVector<const DesktopRootItemRenderData*> visibleBoxItems;
    DesktopOverlayRenderData overlay;
    QSize viewportSize;
    qreal dpiScale = 1.0;
    QColor clearColor = Qt::transparent;
    bool translucentBackground = true;
};
这样后端只吃快照，不碰 ListView 内部状态。

ListView 在新架构里的职责

ListView 保留这些职责：

文件系统和桌面数据更新
m_itemStates 生命周期管理
updateAllItemRenderData()
空间索引和 hit test
选择状态和拖拽状态
维护 dirty region
生成 DesktopSceneSnapshot
也就是说，ListView 从“自己画”变成“组织数据并下发给渲染器”。

现在的 paintEvent()：

paintEvent

未来应该变成这种职责：

void ListView::paintEvent(QPaintEvent* event)
{
    updateAllItemRenderDataIfNeeded();
    DesktopSceneSnapshot snapshot = buildSceneSnapshot(event->region());
    m_renderHost->setSceneSnapshot(snapshot);
    m_renderHost->setDirtyRegion(event->region());
    m_renderHost->render();
}
如果后面换成 QOpenGLWidget，这个调用位置还会再调整一下，不过职责分工就是这个方向。

Raster 后端怎么接现有代码

这个很简单，几乎是平移。

你现在已经有：

paintDesktopRootItemDynamic
paintDesktopRootItemStatic
paintDesktopRootItem
位置在 DesktopItemRenderCacheHelper.h

所以 DesktopRasterRenderBackend 可以直接复用这些函数。

它只是把原来 ListView::paintEvent() 里的循环挪过去：

for (const auto* item : snapshot.visibleDesktopItems) {
    paintDesktopRootItemDynamic(painter, *item);
    paintDesktopRootItemStatic(painter, *item);
}
这样第一步就能完成“架构解耦”，而不影响现有表现。

OpenGL 后端怎么设计

重点是不要直接把 QPainter 代码硬搬进 OpenGL。
那样只会变成“OpenGL 表面，CPU 内核”。

OpenGL 后端应该分三层缓存：

图标纹理缓存
每个文件图标对应一个 GL texture
或者打到 atlas

文本纹理缓存
文件名，阴影，发光先离线生成成 QImage
再上传到 texture
名称变了再重建

静态 item 合成缓存
对非常稳定的 item，可以把静态部分预合成成一张纹理
动态部分单独画

OpenGL 后端的绘制分成三批：

静态图标批次
静态文本批次
动态高亮和框选批次
建议每个 item 最终变成若干个 quad：

icon quad
text quad
selection background quad
hover border quad
shortcut arrow quad

已经有了：

renderDataDirty
位置在 DesktopRootItemState.h

updateAllItemRenderData()
位置在 ListView.cpp

静态和动态绘制分离
paintDesktopRootItemStatic
paintDesktopRootItemDynamic
